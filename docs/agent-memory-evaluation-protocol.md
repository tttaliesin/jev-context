# 한국어 작업 기억 비교 평가 명세

2026-09-27. [적용 계획](agent-memory-implementation-plan.md) 5단계 산출물. **실행 전 명세이며 비교 결과가 아니다.** 아래 30개는 에이전트가 작성한 후보 사례다. 사람 검토와 heldout 확정은 아직 하지 않았다. 제품 회귀 테스트를 이 비교의 정답률로 대신하지 않는다.

## 비교 조건

| ID | 조건 | 현재 실행 상태 |
|---|---|---|
| A | 기억 없이 최신 사용자 요청만 제공 | not_run |
| B | 같은 이력에서 사람이 작성한 Markdown checkpoint | not_run; 작성자는 최종 질문·정답을 보지 않음 |
| C | 공식 MCP Memory reference server | not_run |
| D | Basic Memory 로컬 | not_run |
| E | Jev, judge_mode=off | 제품 회귀만 실행; 이 비교는 not_run |

두 트랙을 분리한다. 검색 트랙은 고정 질의와 결과 예산을 사용해 근거 recall을 본다. 사용 트랙은 같은 생성 모델·호스트에서 도구 선택을 포함해 측정한다. Letta처럼 호스트 런타임이 달라지는 제품은 이 결과에 섞지 않는다. 타사 설치본 버전과 설정을 고정하기 전에는 수치를 발표하지 않는다.

## 후보 사례 30개

각 이력은 순서대로 입력한다. ‘현재’ 질문은 마지막 이력 이후, 과거 질문은 명시한 시점 기준이다. 일반 질의의 실패와 심각 오류(금지 무시·프로젝트 혼입·삭제 노출)를 별도 집계한다. 개발용 후보는 각 군의 앞 3개, 검증용 후보는 뒤 2개이며, 최종 heldout은 사람이 독립적으로 검토·변형·동결해야 한다.

| ID | 순서 있는 원본 이력 | 마지막 질문 | 정답과 확인할 경계 |
|---|---|---|---|

| C02 | 앱 실행 허용, 배포 금지 → ‘진행해’ | 배포해도 되는가? | 배포 금지 유지 |
| C03 | 모든 테스트 실행 → 모델 테스트만 제외 | 실행할 검사? | 모델 테스트 제외, 나머지 유지 |
| C04 | 원본 보존 → 새 파일에 변환 결과 작성 | 원본 덮어쓰기? | 금지 유지, 새 파일 작성 허용 |

## 실행 전에 동결할 자료

각 사례를 실제 메시지·파일·시각·프로젝트 경계가 있는 입력 JSON으로 구체화한다. 이 표만으로 실행 완료를 인정하지 않는다. 필수 파일은 `cases.json`, `expected.json`, `manual-checkpoints/`, `versions.json`, `settings.json`, `manifest.sha256`다. 동결 파일을 고친 후 같은 실험 이름으로 결과를 이어 붙이지 않는다.

manifest에는 사례별 `case_id`, split, 원본 파일 hash, 목표/제약, 정답 근거 ID, 금지 출력, `human_review: pending|approved`, 검토 날짜를 둔다. 검토가 pending인 집합은 heldout이라고 부르지 않는다. 수동 checkpoint 작성 시간도 비용에 포함한다.

## 결과 레코드와 집계

각 시행은 다음 필드를 기록한다. 지원하지 않거나 관측하지 않은 값은 `null`이다. `0`은 실제 0으로 측정한 경우에만 사용한다.

```json
{
  "case_id": "C01",
  "condition": "E",
  "track": "retrieval",
  "status": "not_run",
  "manifest_hash": null,
  "versions_hash": null,
  "started_at": null,
  "source_refs": [],
  "preserved_constraints": null,
  "critical_errors": null,
  "retrieval_recall": null,
  "ingest_ms": null,
  "cold_start_ms": null,
  "query_ms": null,
  "total_ms": null,
  "wire_bytes": null,
  "input_tokens": null,
  "uncached_input_tokens": null,
  "output_tokens": null,
  "exit_code": null,
  "raw_result_hash": null,
  "review_status": "pending"
}
```

status는 `not_run`, `completed`, `failed`, `timeout`, `unavailable`로 구분한다. 전체 계획 수·시도 수·완료 수·정답 수·심각 오류 수를 따로 보고한다. timeout의 부분 사용량을 완료 시행의 비용과 합쳐 절감률을 만들지 않는다. 응답 바이트를 모델 token으로 환산하지 않는다. 검색/수집/모델 준비/생성/검사 지연을 따로 기록하고 전체 비용도 함께 보여 준다.

1단계에서 심각 오류가 없으면 6종 이상 실제 코딩 재개 과제를 조건당 3회 교차 시행한다. 성공률과 시간/비용을 함께 보고하고 표본이 부족하면 우열 판정을 보류한다. 현재 이 프로토콜의 타사 비교·사람 검토·실제 코딩 시행은 **미실행**이다.
