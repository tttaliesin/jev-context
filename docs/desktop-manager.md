# 데스크톱 관리 앱 실행 안내

탐색기에서 프로젝트 폴더의 `dist\JevContext\JevContext.exe`를 더블클릭합니다. Windows x64용 Electron 관리 앱 **0.7.0**입니다. 기존 **Python 서비스 0.2.0**과 같은 프로젝트 설정·모델·작업 기록을 사용합니다.

프로젝트 전환은 새 연결 확인과 설정 저장이 모두 성공한 뒤 반영합니다. 저장에 실패하면 기존 프로젝트를 유지하므로 파일 접근 문제를 해결한 뒤 다시 선택할 수 있습니다. Python 시작 실패 뒤 상태를 다시 조회하면 새 프로세스로 연결을 시도합니다.

0.6.0에서 추가한 Workroom 직접 연결 파일 내보내기는 제거했습니다. Codex·Claude Desktop의 에이전트가 각 제품 MCP를 독립적으로 사용합니다. 기존 전용 저장 파일은 자동 삭제·이관하지 않습니다. [독립 제품 원칙](independent-products.md) · [일반 기억 도구 사용](agent-memory-workflow.md)

앱에서 모델 상태와 저장된 작업을 관리하고, 코딩 대화와 작업 지시는 Codex에서 계속합니다.

## 한국어 / English — 0.5.0

문제 해결 창에서도 언어를 변경할 수 있습니다.

상단 또는 첫 연결 창의 언어 선택에서 **한국어 / English**를 선택합니다. 즉시 반영되며 앱을 다시 열어도 유지됩니다. 작업 선택·필터·연결 단계와 입력값을 유지하고, 작업 원문·경로·설정/Skill 미리보기는 번역하지 않습니다. 날짜와 앱 안내는 선택한 언어를 따릅니다. 파일 선택창의 기본 버튼은 Windows 언어 설정을 따릅니다.

언어는 Electron 사용자 데이터 폴더의 `settings.json`에 저장하며 프로젝트와 Python 경로도 보존합니다. 저장 실패 시 기존 언어를 유지하고 오류를 표시합니다. [구현과 검증](desktop-language-plan.md) · [English README](../README.en.md)

## 처음 연결하기 — 0.4.0

프로젝트 설정이 없거나 현재 설치할 MCP·Skill과 일치하지 않으면 연결 안내가 열립니다. 상단 **Codex 연결** 또는 빠른 실행의 같은 명령으로 언제든 다시 열 수 있습니다.

1. **프로젝트:** 폴더를 선택합니다. 새 프로젝트에서는 파일 허용 범위를 확인하고 **프로젝트 준비**를 누릅니다. `.local/project.toml`과 빈 작업 DB를 만들며 모델과 자동 파일 수집은 꺼져 있습니다. 기존 프로젝트는 현재 설정·DB·모델 프로필을 그대로 사용합니다. 별도 위치에 저장한 TOML은 **기존 설정 파일 열기**로 선택합니다.
2. **Codex 연결:** Jev MCP 항목과 Skill 내용, 실제 설치 경로, 유지·새로 설치·백업 후 갱신 여부를 보고 **설정 적용**을 누릅니다. 미리보기 이후 파일이 바뀌면 **변경 내용 다시 보기**가 필요합니다. 다른 MCP·설정 항목을 보존합니다.
3. **연결 확인:** **서버 통신 점검**으로 로컬 MCP 경로를 검사합니다. 같은 폴더를 Codex에서 열고 프로젝트 신뢰를 확인한 다음 MCP 설정을 다시 읽으세요. 미반영 시 Codex를 재시작합니다. 앱의 **확인 문구 만들기 → 확인 문구 복사**를 눌러 Codex 대화에 붙여넣으면, 해당 도구 요청 수신 여부를 앱이 자동 갱신합니다.
4. **시작:** 작업 화면으로 돌아갑니다. Codex 호출 확인을 나중에 할 수도 있으며, 앱은 이 경우 미확인으로 남깁니다.

연결 화면은 설정 적용·MCP 서버 응답·Codex 확인 요청을 따로 표시합니다. 확인 문구는 10분간 유효하며 설정이 바뀌면 무효가 됩니다. MCP의 클라이언트 이름에 `codex`가 포함되고 일회성 요청 ID가 일치한 성공 호출만 기록합니다. 이름은 클라이언트가 보고한 값이며 대화 신원 인증·지속 연결 증거는 아닙니다. 현재 대화 연결을 직접 관측하지 않는 기존 관리 화면의 상태도 유지합니다.

**설정 되돌리기**를 두 번 눌러 마지막 연결 설치 전의 파일로 복원할 수 있습니다. 앱이 새로 설치한 연결 파일은 제거하지만 프로젝트 설정과 작업 DB는 남깁니다. 백업과 설치 기록은 프로젝트 `.local/jev-setup`에 저장합니다. 설치 후 파일을 별도로 수정했다면 해당 변경을 덮어쓰지 않고 복원을 거절합니다. 설치 도중 중단된 경우도 같은 버튼으로 복구합니다.

Python을 찾지 못하면 **Python 선택**에서 Jev 의존성이 설치된 Python 3.12 실행기를 고르고 다시 진행합니다. 현재 배포는 Python·모델 파일을 포함한 독립 설치 프로그램이 아닙니다. 모델 없이 작업 저장·검색을 시작할 수 있으며, 모델 가중치 다운로드·프로필 생성은 이번 안내에 포함하지 않습니다.

## 프로젝트와 작업 기록 열기

처음 실행하면 이 프로젝트의 `.local\project.toml`을 사용합니다. 다른 설정을 열려면 **상단 프로젝트 이름 왼쪽의 폴더 버튼**에서 기존 프로젝트의 TOML 설정 파일을 선택합니다. 선택한 설정은 다음 실행에도 사용됩니다.

- 왼쪽 **작업 기록**에서 저장된 작업을 선택하면 목표, 유지할 제약, 최근 진행 내용과 남은 확인 사항을 볼 수 있습니다.
- 상단의 목록 접기 버튼이나 `Ctrl+B`로 사이드바를 접고 펼칩니다. 접으면 사이드바 폭이 **0px**가 되어 작업 본문에 공간을 돌려주며, 상단 토글과 **빠른 실행**은 남습니다.
- 사이드바 기본 폭은 **260px**입니다. 오른쪽 경계를 드래그하거나 Tab으로 경계에 접근한 뒤 좌우 방향키로 조절합니다. 범위는 **220–400px**이며 작은 창에서는 본문 공간을 위해 상한이 낮아집니다. 경계에서 Home·End는 최소·최대 폭, Enter는 접기입니다. 더블클릭하면 기본 폭으로 돌아갑니다.
- **불러온 작업 필터** 또는 `Ctrl+F`는 현재 불러온 작업의 제목과 목표에서 찾습니다. 필터 아래에 대상 개수와 추가 기록 여부를 표시합니다. 결과가 없으면 **필터 초기화**로 돌아가거나, 다음 페이지가 있을 때 **작업 더 보기**로 이전 기록을 추가로 불러옵니다. 추가 조회 후에도 필터와 선택 작업을 유지합니다.
- 필터 입력창에서 `Enter`는 첫 결과를 열고, `Esc`는 필터를 초기화하며, 아래 방향키는 목록으로 이동합니다. 목록에서는 위·아래·Home·End로 이동하고 Enter 또는 Space로 작업을 선택합니다.
- 상단 **빠른 실행** 또는 `Ctrl+K`는 화면·연결·모델 명령과 **불러온 작업**을 찾는 창을 엽니다. 화살표로 이동하고 Enter 또는 클릭으로 실행하며 Esc로 닫습니다. 접힌 상태에서도 기록을 열 수 있고, 빠른 실행을 열거나 기록을 선택하는 것만으로 접힘 설정을 바꾸지 않습니다. 전체 작업 DB나 시스템 전체를 검색하는 기능은 아닙니다.
- 상단 **?** 버튼이나 `F1`로 단축키 안내를 엽니다. 닫기 버튼이나 `Esc`로 닫으면 원래 조작 위치로 돌아갑니다.
- 새로고침 버튼이나 `F5`·`Ctrl+R`로 상태와 기록을 다시 읽습니다. 작업 생성·수정과 코딩 지시는 Codex의 기존 작업 흐름에서 수행합니다.

마지막 선택 작업과 목록 필터는 **프로젝트별로** 기억합니다. 다시 열 때 저장된 작업 ID로 현재 기록을 다시 읽으며, 과거 상세 내용을 그대로 현재 결과로 표시하지 않습니다. **사이드바 폭과 접기 상태는 앱 전체에서 공통으로** 기억하고 재실행 시 복원합니다. 창의 위치·크기와 최대화 여부도 복원하며, 모니터 구성이 바뀌면 현재 화면 안에서 열리도록 조정합니다.

상단에는 프로젝트와 현재 작업 이름을 표시하고 마지막 조회 시각은 하단에 표시합니다. 같은 작업의 내용이 갱신될 때는 읽던 스크롤 위치를 유지하고, 다른 작업을 선택하면 본문 맨 위에서 시작합니다. 자동 상태 조회는 목록 로딩 표시와 더 보기 문구를 매번 바꾸지 않습니다. 첫 조회·수동 조회와 상세 읽기의 로딩, 조회 실패는 해당 위치에 표시합니다.

작업을 불러오지 못하면 상세 영역의 오류와 **작업 다시 불러오기** 버튼으로 재시도합니다. 실패한 작업의 상세 조회를 주기적 상태 갱신 때마다 반복 재시도하지 않습니다.

저장된 진행·완료 내용은 기록의 출처에 따라 표시됩니다. 에이전트가 보고한 완료를 관리 앱이 독립 검증한 결과로 바꾸어 표시하지 않습니다.

## 문제 해결 — 0.7.0

연결 영역의 **문제 해결**, 오류 안내의 같은 버튼, 빠른 실행에서 엽니다. Esc 또는 닫기로 닫으면 원래 위치로 포커스가 돌아갑니다.

- **앱 연결 다시 연결:** 현재 프로젝트에 새 bridge 연결을 만든 뒤 조회 성공 시 교체합니다. 실패하면 기존 연결을 유지하며, 설정 파일 쓰기·작업 삭제·모델 재시작을 하지 않습니다. 다른 요청이 처리 중이면 완료 후 사용할 수 있습니다.
- **진단 요약:** 앱/Electron/Node 버전, 실행 파일·설정 존재 여부, 마지막 조회 시각과 연결/모델 상태, 최근 실패 코드를 확인합니다. ‘복사할 내용 보기’에서 확인한 동일 문자열을 복사하며, 경로·작업 제목/본문·환경 변수·raw 로그는 포함하지 않습니다. 서버가 응답하지 않아도 마지막 관측과 앱 상태를 읽을 수 있습니다. 현재 상태나 Codex 연결을 새로 검증한 결과로 표시하지 않습니다.
- **조회 재시도:** 연속 실패하면 12→24→48→60초 간격으로 기다립니다. 화면에 간격을 표시하고 수동 새로고침은 즉시 가능합니다. 창이 숨겨지면 자동 조회를 중단하며, 돌아오면 상태를 재확인하기 전까지 모델 제어가 잠깁니다.

앱 재연결은 Codex가 가진 MCP 연결의 재시작과 별개입니다. Codex에 이전 서버 코드가 남아 있으면 해당 호스트에서 MCP를 재시작하고 실제 도구 호출로 확인해야 합니다. [비교 연구와 적용 결과](desktop-operations-research.md)

## 모델 준비와 종료

앱 열기, 프로젝트 선택, 상태 조회, 작업 기록 조회, 목록 필터링, 빠른 실행 창 열기·검색과 **연결 점검**은 모델을 시작하지 않습니다. **모델 준비** 버튼을 누르거나 빠른 실행에서 해당 명령을 선택해 실행하면, 선택된 프로젝트에 구성된 로컬 모델의 준비를 명시적으로 요청하고 화면이 준비 상태를 갱신합니다. Codex에서 실제 모델 판단을 요청할 때도 같은 공유 실행기를 사용할 수 있습니다.

현재 설치의 유휴 해제 시간은 **120초**입니다. 준비 완료 또는 마지막 판단 이후 사용되지 않으면 모델 메모리를 해제합니다. 화면의 자동 상태 갱신은 이 시간을 연장하지 않습니다.

**모델 종료**는 선택된 모델의 공유 실행기에 종료를 요청합니다. 준비 중이거나 판단 요청을 처리 중이면 종료를 거절합니다. 강제로 프로세스를 종료하지 않습니다. 여러 MCP 연결이 같은 모델을 공유하므로 종료는 그 공유 모델에 적용됩니다.

관리 앱 창을 닫으면 앱의 연결을 닫습니다. 공유 모델을 강제 종료하지 않으며, 계속 사용되지 않는 모델은 기존 유휴 정책에 따라 해제됩니다.

**진단 정보**를 펼치면 모델 오류와 프로젝트 경로를 볼 수 있습니다. `Esc`를 누르거나 진단 영역 바깥을 클릭하면 닫힙니다.

## 연결 점검의 의미

화면은 **관리 도구**, **MCP 통신**, **현재 Codex 대화**를 나누어 표시합니다.

**연결 점검**은 별도 로컬 MCP 서버에 표준 입출력으로 연결하여 도구 목록과 프로젝트 상태 응답을 확인합니다. 모델을 준비하거나 판단을 실행하지 않습니다. 성공하면 이 프로젝트의 MCP 통신 경로가 동작한다는 뜻입니다.

이 검사는 현재 Codex 대화에 MCP가 연결되어 있는지를 직접 관측하지 않습니다. 따라서 별도 점검이 성공해도 **현재 Codex 대화**는 **직접 관측 안 함**으로 표시됩니다. Codex 연결 설정은 [기존 연결 안내](codex-setup.md)를 따릅니다.

모델 프로필이나 공유 실행 코드를 변경한 경우, 변경 전에 시작된 MCP 연결에는 새 내용을 적용하기 위한 재시작이 필요할 수 있습니다. 해당 연결을 제공하는 Codex를 완전히 종료한 뒤 다시 실행합니다. 이는 변경 시의 일반적인 적용 절차이며, 현재 서버가 구버전 프로필을 사용한다는 뜻은 아닙니다. 관리 앱의 별도 MCP 점검만으로 Codex 서버의 재시작 여부를 판단하지 않습니다.

## 설치 위치와 실행 환경

현재 빌드는 이 PC의 다음 파일을 사용합니다.

- 프로젝트의 `.venv\Scripts\python.exe`와 `src\jev_context`
- 선택한 프로젝트 설정 파일과 그 설정이 가리키는 모델 프로필
- `.local`에 준비된 모델 파일·모델 실행 환경·기존 작업 DB

실행 파일 옆 `launch-config.json`에는 프로젝트, Python 실행기, 기본 프로젝트 설정의 경로가 기록됩니다. 앱 폴더에는 모델과 Python 환경, 작업 DB가 함께 포함되어 있지 않습니다. **`dist\JevContext`만 다른 PC로 복사하면 그대로 동작하지 않습니다.** 실행 파일만 폴더 밖으로 옮기지 말고 같은 폴더의 Electron 실행 파일들을 함께 유지합니다.

설정 파일을 찾지 못하면 상단의 **프로젝트 설정 열기** 버튼에서 올바른 설정을 선택합니다. Python 실행 환경이나 프로젝트 소스 경로를 찾지 못하면 실행 파일 옆 `launch-config.json`과 실제 설치 위치를 확인합니다. 프로젝트와 DB 자체를 옮기는 작업은 [프로젝트 이동 복구 기록](recovery-validation.md)에 설명한 별도 경로·이력 검증이 필요합니다.
