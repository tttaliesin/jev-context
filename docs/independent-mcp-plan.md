# 독립 MCP 구조로 정정하는 적용 계획

2026-09-27. 사용자가 Workroom 대화에서 각 제품을 Codex·Claude Desktop에 연결해 에이전트가 사용하면 된다고 정정하고 진행을 승인했다. 직접 앱 연결 구현은 이 방향과 맞지 않는다.

1. `44e3035`에서 추가한 Workroom 전용 MCP 3개, 전용 저장 모듈, 실행 설명 CLI/진입점, Electron 내보내기 UI/IPC와 전용 테스트를 제거한다. 그 전 Jev 일반 MCP 1.0/2.0, 모델 관리, Codex 연결, 한영 전환은 유지한다.
2. 기존 데이터 파일은 열거나 삭제·이관하지 않는다. `.local` 등 검증용 산출물도 자동 청소하지 않는다. 폐기된 직접 연결 기능은 기존 전용 DB에 접근할 경로를 더 이상 제공하지 않는다.
3. 독립 제품 원칙과 에이전트 사용 안내를 실제 일반 MCP schema에 맞춰 쓴다. Workroom은 결과 원본, Jev는 허용된 범위의 기억이며 에이전트가 필요할 때 각 서버를 호출한다. 서버 등록만으로 자동 기억하지 않는다.
4. 배포되는 Jev Skill에 다른 도구에서 읽은 결과의 저장 시점·출처·범위·재시도 원칙을 보완한다. 특정 제품의 ID 체계나 별도 upsert 계약을 추가하지 않는다. 설치된 사용자 Skill과 호스트 설정은 자동 수정하지 않는다.
5. 일반 MCP 프로세스를 새로 열어 작업 저장, 출처 있는 발췌 등록, 서버 재시작 후 복원·검색을 검사한다. 허용 목록 밖 수집 금지, 모델 미기동, 기존 전용 데이터 불변, 폐기 명령·도구 미노출도 검사한다.
6. Python 전체 회귀, Node 언어·창 상태, 렌더러 시나리오, 앱 빌드를 확인한다. 제거된 UI가 패키지에도 없는지 확인하고 앱 버전을 0.6.1로 올린다. Jev 저장소만 커밋·푸시하고 결과를 Workroom 담당 대화에 전달한다.

완료 근거는 `independent-mcp-results.md`에 기록한다. 공식 MCP SDK 검사는 Codex·Claude Desktop 실제 호스트의 연결 성공과 구분한다. 호스트 설정 변경, 사용자 원본 결과 수집, 일반 코딩 효율 입증은 이번 범위가 아니다.
