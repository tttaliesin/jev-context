# Workroom과 Jev Context: 독립 제품과 선택적 연동

상태: 사용자 결정 반영, 2026-09-27.

## 유지할 원칙

- 두 저장소는 계속 분리한다. 모노레포, submodule, 상대 경로 import, 공동 DB로 합치지 않는다.
- 각각 설치·배포·버전 관리하며 상대 제품 없이 핵심 기능을 사용할 수 있다.
- Workroom은 작업 요청·실행·검토·승인·포트폴리오를 책임진다.
- Jev Context는 장기 작업 기억·제약·근거·문맥 검색과 복원을 책임진다.
- 독립 사용에 필요한 기록·검색은 양쪽에 존재할 수 있다. 연동은 기본 꺼짐이며 기존 기능을 제거하지 않는다.

## 데이터 소유권

Workroom의 실행 상태, 사용자 승인, 작업 결과와 포트폴리오가 원본이다. Jev는 사용자가 전송을 확인한 작업 결과의 파생 기억을 보관한다. Jev 응답으로 Workroom 작업을 완료·승인하거나 포트폴리오를 덮어쓰지 않는다. Jev에서 독립적으로 관리한 목표·제약·근거는 Jev 소유이며 이 연동이 수정하지 않는다.

원본 ID와 revision으로 파생 기억을 식별한다. 같은 버전 재전송은 중복을 만들지 않고, 같은 버전의 다른 내용과 역순 갱신은 거부한다. 연결 해제는 기록 삭제가 아니다. 양쪽 삭제·보존 정책은 명시적인 별도 동작으로 유지한다.

## 연결 경계

버전이 명시된 MCP stdio 계약만 사용한다. Workroom은 사용자가 지정한 실행 설명 파일을 읽으며 Jev의 DB, 내부 Python 코드, 설치 폴더를 추측하지 않는다. 상대 저장소가 없어도 빌드·테스트가 가능해야 한다. 계약에 호환되지 않거나 연결이 실패하면 명확히 표시하고 원래 작업·기록 기능은 유지한다.

두 검색을 몰래 동시에 실행하거나 결과를 합치지 않는다. 첫 버전은 사용자가 별도로 요청하는 Jev 기억 검색이며 기존 Workroom 검색과 에이전트 문맥은 변경하지 않는다. 자동 문맥 공급이나 기존 검색 대체는 공통 평가를 거친 후 별도 버전으로 결정한다.

## 사용자 경험

Workroom 안에서 제품별 연결 설정, 연결 검사, 전송 내용 검토, 명시적 전송과 외부 기억 검색을 제공한다. 자동 전송·모델 시작·숨은 Codex 설정 변경은 하지 않는다. 한영 UI를 유지한다. Jev의 독립 관리 앱도 계속 유지한다.
