# Workroom과 Jev Context: 독립 제품

2026-09-27 사용자 정정 반영. 이전 앱 간 직접 연결 설계를 대체한다.

두 저장소는 계속 별개로 유지한다. 모노레포, submodule, 상대 저장소 import, 공동 DB를 사용하지 않는다. 각자 설치·배포·버전을 관리하고 상대 제품 없이 핵심 기능을 제공한다.

- Workroom은 작업 요청·실행·검토·승인·결과 원본을 관리한다.
- Jev Context는 목표·제약·결정·근거의 장기 기억과 검색·복원을 제공한다.
- Codex·Claude Desktop 같은 호스트의 에이전트가 필요한 MCP 도구를 각각 호출한다. 앱끼리 직접 연결하지 않는다.

Jev가 Workroom을 직접 수집하거나 Workroom이 Jev로 전송하는 기능은 두지 않는다. Jev의 작업 기억이 Workroom의 실행·승인 상태를 변경하지 않는다. 에이전트가 읽어 저장한 결과는 출처가 있는 보고 자료이며 검증·승인을 대신하지 않는다.

두 MCP 서버를 등록하는 것만으로 자동 저장·검색이 되지는 않는다. 호스트에서 사용할 에이전트 지침으로 저장 시점과 허용 범위를 정한다. 실제 도구 호출과 결과를 확인해야 저장·복원 성공으로 보고할 수 있다. [일반 도구 사용 흐름](agent-memory-workflow.md) · [적용 계획](independent-mcp-plan.md)

## 기존 직접 연결 사용자

0.6.0의 Workroom 전용 bridge와 연결 파일 내보내기는 0.6.1에서 제거했다. 이전 연결 JSON의 진입점도 더 이상 제공하지 않는다. 기존 전용 DB는 자동 삭제·이관하지 않으며 일반 검색에 포함하지 않는다. 해당 파일이 남아 있다면 보존된 과거 데이터이지 현재 동기화 상태가 아니다. 삭제나 일반 기억으로의 이관은 사용자가 범위를 지정한 별도 작업으로 처리한다.
