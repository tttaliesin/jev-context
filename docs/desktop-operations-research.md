# 운영 경험 비교 연구와 0.7.0 적용 계획

조사일: 2026-09-27. 대상: Jev 0.6.2. 목적은 사용자가 연결 문제를 구분하고 앱 안에서 복구·진단할 수 있게 하는 것이다. 공식 문서와 공개 소스를 읽었으며 타사 제품을 직접 설치해 사용성 실험을 한 것은 아니다.

에이전트 기억·문맥 복원이라는 제품 목적이 겹치는 Mem0·Zep/Graphiti·Supermemory·Letta·Basic Memory·LangMem·MCP Memory 비교는 [별도 연구](agent-memory-competitive-research.md)에 정리했다. 이 문서는 운영 UX 비교와 0.7.0 적용 기록이다.

## 비교 근거

| 제품·프로젝트 | 확인한 동작 / 1차 출처 | Jev에 대한 판단 |
|---|---|---|
| Docker Desktop (상용) | [Troubleshoot](https://docs.docker.com/desktop/troubleshoot-and-support/troubleshoot/)에 재시작·지원·진단 수집을 제공한다. 진단 수집과 업로드가 별도 단계다. | 오류 메시지에 더해 사용자가 접근할 수 있는 문제 해결 창과 복구 동작이 필요하다. 로컬 앱인 Jev는 업로드 없이 진단 미리보기·복사부터 제공한다. |
| VS Code (공개 소스) | [Remote SSH 안내](https://code.visualstudio.com/docs/remote/ssh)는 연결 진행 알림과 상세 로그 경로를 설명한다. [연결 구현](https://github.com/microsoft/vscode/blob/main/src/vs/platform/remote/common/remoteAgentConnection.ts)은 연결 손실·대기·재연결 상태와 지연된 재시도를 분리한다. | 조회 실패를 무한한 동일 간격 폴링으로만 처리하지 않고 다음 재시도를 표시한다. 사용자의 즉시 재시도는 계속 허용한다. |
| GitHub Desktop (공개 소스) | [문제 해결 안내](https://docs.github.com/en/desktop/installing-and-authenticating-to-github-desktop/authenticating-to-github-in-github-desktop)는 오류 안내와 Help → Show Logs를 연결한다. | 현재 버전·마지막 성공/실패·연결 상태를 한곳에서 확인하고 복사할 수 있어야 한다. 작업 내용과 경로가 섞일 수 있는 raw 로그 대신 허용 필드로 구성한 요약을 쓴다. |
| LM Studio (로컬 모델 제품) | [Idle TTL / Auto-Evict](https://lmstudio.ai/docs/developer/core/ttl-and-auto-evict)는 미사용 모델의 해제와 여러 모델 전환 시 메모리 회수를 설명한다. | Jev는 유휴 해제와 명시적 모델 준비가 이미 있다. 상태 조회·재연결·진단 열기가 모델을 시작하지 않는 기존 경계를 검증하고 유지한다. |

출처에서 확인한 동작과 Jev에 대한 적용 판단을 구분했다. 브랜드의 외형이나 코드를 복제하지 않고 현재 제품의 실패 사례에 해당하는 동작만 적용한다.

## 현재 부족한 부분

0.6.2는 설정 저장의 원자성과 spawn 실패 복구를 고쳤지만, 정상적으로 살아 있으면서 응답하지 않는 앱 bridge를 사용자가 새 연결로 교체할 경로가 없다. 오류 화면의 ‘다시 시도’는 상태 조회이며 새 연결과 다르다. 앱 버전과 연결 요약을 공유하려면 터미널·스크린샷이 필요하다. 자동 조회는 준비 중 2.5초, 그 외 12초 고정이어서 장기 실패에도 같은 빈도로 재시도한다. 창 복귀 시 마지막 모델 상태가 조회 완료 전까지 제어 가능한 상태로 남는 구간도 있다.

## 이번 구현 범위

1. **문제 해결 창:** 연결 영역·오류 영역·빠른 실행에서 접근. 현재 설치 버전과 진단 미리보기, 새로 읽기, 복사, 앱 연결 다시 연결 제공. 한국어/영어·키보드·좁은 창 지원.
2. **앱 연결 다시 연결:** 현재 설정으로 새 bridge를 만들고 overview 성공 후 기존 bridge 교체. 실패 시 기존 연결 유지. 설정 파일을 다시 쓰지 않는다. 동시 전환·대기 중인 요청이 있으면 중단시키지 않고 기다리도록 안내한다. 다른 호스트 MCP나 공유 모델을 종료하지 않는다.
3. **진단 요약:** 버전·런타임·설정 파일 존재 여부·bridge 상태·마지막 성공 시각·실패 코드·모델/연결 상태를 제한된 필드로 구성. 사용자명·절대 경로·작업 제목/원문·환경 변수·raw stderr는 포함하지 않는다. 복사 버튼은 화면에 표시한 동일 문자열을 복사한다. 자동 외부 전송은 없다.
4. **조회 실패와 복귀 처리:** 연속 실패 후 12→24→48→60초 대기, 성공 시 원래 간격으로 복귀. 다음 자동 재시도 간격 표시, 수동 조회 즉시 실행. 숨겨진 창에서 폴링 중단, 복귀 시 현재 상태를 다시 확인하기 전 모델 제어 잠금. 조회 실패/복구 때 안내를 제공하되 작업 자체를 자동 재실행하지 않는다.

12/24/48/60초는 Jev의 로컬 조회 비용과 기존 12초 간격을 고려한 설계 선택이며 타사 성능을 실측해 도출한 숫자는 아니다.

## 후속 과제와 채택하지 않은 항목

- **호스트 코드 최신성 식별:** 이전 감사의 현재 Codex MCP는 구버전 응답이었다. 앱 bridge 재연결과 호스트 MCP 재시작은 별개다. 실행 중인 각 호스트의 코드 지문을 계약에 추가하고 업그레이드 전후 호환 검사를 거친 뒤 자동 판정하는 후속 작업이 필요하다. 이번 기능을 그 해결로 표시하지 않는다.
- **독립 설치·서명·자동 업데이트:** Python 포함 배포, 코드 서명, 릴리스 경로, 롤백 정책을 먼저 정해야 한다. 자동 updater만 연결해서 설치 문제를 해결했다고 보고하지 않는다.
- **최근 프로젝트 목록:** 편의성은 있지만 최근의 복구 결함보다 우선순위가 낮아 후속으로 둔다.
- **자동 모델 로딩·강제 프로세스 종료·공장 초기화:** 다른 세션과 모델을 공유하는 현재 구조에 맞지 않아 이번에 추가하지 않는다.

## 완료 기준

- 기존 Node/Python 검사 통과, 신규 reconnect의 성공·실패·busy·설정 저장 비접근 검사.
- 진단 미리보기와 복사 문자열 일치, 민감한 테스트 문자열 미포함, bridge 실패 중에도 진단 열기 가능.
- 실제 renderer에서 대기 증가·복구·숨김/복귀·모델 제어 잠금·한국어/영어·포커스 복원 검사.
- 실제 Electron에서 진단·재연결 후 기록/선택/언어 유지, 모델 미실행, 사용자 데이터 비변경 확인.
- 빌드·문서·영문 README 버전 갱신, 커밋·원격 반영, 해당 CI 결과 확인.

## 적용 및 로컬 검증 결과

위 1–4번 범위를 0.7.0에 구현했다. 진단은 `desktop/diagnostics.cjs`에서 허용 필드로 구성하고 Electron main이 보관한 미리보기를 그대로 복사한다. 재연결은 새 bridge 검증 후 교체하며 설정 파일에 접근해 저장하지 않는다. 동시 전환과 진행 중인 요청을 검사한다. 반복 실패의 동일 안내를 매번 다시 알리지 않도록 했다.

Electron은 실제 프로세스·IPC·파일 쓰기를 사용했고 OS 파일 선택 결과만 격리 경로로 대체했다. 모델/GPU를 시작하거나 사용자 실제 프로젝트의 기록을 변경하지 않았다. 한국어 오류 창과 실제 영어 진단 창 스크린샷도 직접 열어 확인했다.

실제 호스트 MCP가 현재 코드로 다시 연결됐다는 검증, 모델 판단 정확도 평가, 타사 앱 직접 실행 비교는 수행하지 않았다. 위 후속 과제는 이번 완료 항목에 포함되지 않는다.
