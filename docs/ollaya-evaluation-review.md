# Ollaya 계획 사전 검토

2026-09-28 KST. 작성자가 구현·설치·추론 전에 수행한 자체 검토이며 독립 검토 또는 사용자 승인을 의미하지 않는다. [확정 계획](ollaya-evaluation-plan.md).

| 검토 항목 | 발견 내용 | 조치 |
|---|---|---|
| 제품 교체 근거 | 에이전트가 만든 30개 최종 사례로 실사용 품질을 보증할 수 없음 | 진단 실행만 확정. 제품 교체와 promotion은 이번 산출물에서 제외하고 후속 후보 판정으로 제한 |
| 튜닝 누출 | 최종 결과를 보고 질문이나 threshold를 바꾸면 검증 의미 상실 | 두 질문·분할·선택 규칙을 선고정하고 개발 선택 파일 저장 후 최종 실행 |
| calibration 의미 | temperature는 정확도를 올리는 학습이 아님. 기존 확률에 맞춘 온도를 그대로 넣으면 이중 보정 | 기존 온도 × 상대 온도로 변환, 공통 버킷 하나 사용, 반올림 근사와 실제 응답 확인 |
| 보류율 | 모델의 근거 부족 선택을 수락으로 세면 왜곡됨 | 최대 확률 기준과 별개로 insufficient_evidence는 항상 보류 |
| 장치·속도 비교 | CPU Laya와 GPU Qwen은 실행기만의 A/B가 아님 | 현재 PC에서 사용할 두 구성의 비교로 한정, 모델·장치·캐시·첫 추론을 표시 |
| 자원과 격리 | 포트·모델 경로만 분리해도 자동 시작/동시 상주 가능 | 활성 프로세스 확인, portable 실행, 한 모델씩 명시적 준비·해제, RAM 하한 명시 |
| 재현성 | 버전 태그가 같아도 registry 모델이 갱신될 수 있음 | 공식 zip checksum과 모델 manifest/blob hash를 함께 보존 |
| 실패 집계 | 시간 초과·중단 사례 제외 시 정답률 과대평가 | 오류를 분모에 유지, not_run 별도 표시, 조용한 재시도 금지 |
| 유지보수 | 비교 전에 새로운 제품 어댑터를 만들면 불필요한 레이어 발생 | 독립 실험 도구만 추가하고 통합 후보 기준 충족 여부부터 확인 |

검토 결과: 위 보완을 계획에 반영했다. 설치와 한국어 진단·튜닝을 실행할 수 있다. 계획을 바꿔야 할 새 사실은 결과 보고서에 이유와 영향을 남기고, 최종 사례를 본 뒤 선택 규칙을 바꾸지 않는다.
