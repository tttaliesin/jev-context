적용 범위는 다음과 같이 유지한다.

- 작업 저장·원문 검색·재시작 후 복원은 검증한 기능으로 사용한다. 이 기능이 이번 코딩 과제의 시간이나 입력 토큰을 줄였다고 주장하지 않는다.
- 현재 로컬 판단은 실험용 `shadow` 관찰로 유지한다. 자동 선별을 활성화할 근거가 없으며 승격하지 않는다.
- 명세가 충분한 한 결함, 조건당 세 번, 에이전트가 작성한 검사라는 한계가 있다. 모든 수정본이 검사를 통과해 품질 차이를 구별하기 어려웠다. 일반 효과나 모델의 한국어 정확도는 별도 과제·사람이 검토한 heldout 평가가 필요하다.
- Codex 실행 중 Windows 긴 임시 경로와 자체 추가 검사의 기대값·정리 오류를 고친 시간이 포함된다. 소표본·시간 제한·외부 응답 지연을 고려하면 조건 간 인과관계를 확정할 수 없다.

## 수정 비교의 범위

E0/E1/E2 각 3회, 총 9회의 새 Codex 실행을 별도 복사본에서 순서 교대한다. 모든 조건에 동일한 정책 원문·공개 요구사항·수정 전 코드를 제공하고 E1/E2에만 준비한 MCP 문맥을 더한다. 준비한 문맥은 반복 간 동일하므로 이 부분은 한 번 측정한 비용이다. 코드 수정 구간의 차이에 준비 비용을 숨기지 않고 별도로 표시한다.

공개 검사 13개는 수정 전 모두 통과했다. 숨은 회귀 검사 13개는 수정 전 7개 실패·6개 통과, 별도 수정 참조본에서 13개 모두 통과했다. 소스·원문·문맥·요구사항·채점·실행기는 첫 실행 전에 동결했다. 사용자의 모델·추론 설정을 변경하지 않았으며 실제 각 실행 기록에서 확인한다.

사전 CLI 확인의 첫 실행은 존재하지 않는 MCP 설정을 끄는 인수 때문에 모델 호출 전 실패했다. 실제 설정에 존재하는 서버만 비활성화하도록 수정한 다음 사전 확인이 성공했다. 평가 본 시행과 이 실패를 분리해 보존했다.

최초 묶음 `rb1`의 E0 시행은 236.437초, 공개·숨은 검사 26개 통과, 허용 소스 두 개만 변경으로 끝났다. 실제 모델 `gpt-6-astra`와 추론 강도 `ultra`도 확인했다. 다음 시행 전에는 CLI가 자기 평가 폴더의 `trust_level="trusted"` 항목을 사용자 설정에 자동 추가한 탓에 전체 파일 hash 검사가 중단됐다. 검사기를 고쳐 **해당 묶음의 정확한 trial 경로에 새로 추가된 순수 trust 항목만** 구분하고, 나머지 설정은 전체 TOML 의미 구조의 hash로 계속 검사한다. 원본 파일 hash도 기록한다. 최초 성공·중단 기록은 보존하고 최종 비교에 섞지 않는다.

두 번째 묶음 `rb2`는 `rb1`의 아직 실행하지 않은 복사본에서 동일한 수정 전 제품 코드·공개 검사를 다시 가져왔다. 제품 수정이 그 사이 진행됐어도 평가 입력은 바뀌지 않았다. 과제·정책·문맥·숨은 검사 내용을 유지하고 순서의 처음부터 9회를 시도했다.

9회 모두 CLI가 `usage limit` 오류와 exit code 1을 반환했고 정상 완료한 turn은 없었다. 첫 E0는 일부 수정을 남겨 공개·숨은 검사가 통과했지만 최종 응답 없이 중단됐으므로 완료 성공으로 세지 않는다. 나머지 8회는 약 4초 만에 제한 오류로 끝났다. 이는 모델의 수정 능력을 비교한 결과가 아니다.

이전 집계기의 `completed_trials=9`는 결과 파일이 있는 시도를 센 것이었고, 시간 중앙값에도 제한 오류 종료 시간을 넣었다. 원본 `.local/rb2/results.json`은 변경하지 않았다. 새 집계기와 각 시행의 오류 이벤트로 별도 재집계한 `.local/resume-20260927/rb2-reanalysis.json`은 **시도 9회, 정상 완료 0회, 성능 시간·토큰 중앙값 null**이다. 과거 약 4초 수치를 코딩 시간이나 조건 간 효율 비교에 사용하지 않는다.

## 평가 집계 수정

`scripts/resume_benchmark.py`는 시도 수·정상 완료 수·성능 표본 수를 구분한다. 비정상 종료와 범위 위반의 시간·부분 토큰은 성능 중앙값에서 제외하며, 정상 종료했지만 정답 검사에 실패한 수정은 포함한다. 사용량 제한 오류를 원본 이벤트와 함께 기록하고 같은 묶음의 후속 시행을 차단한다. 준비 시간을 포함하지 않는 추정 필드도 `estimated_context_call_plus_replay_seconds`로 이름을 바꿨다.

이 동작의 회귀 6개를 추가했고, 관련 검사 22개가 통과했다. 최종 `scripts/check.py`는 lint·format과 전체 **262개 통과·기존 Windows symlink 권한 조건 1개 제외**로 exit code 0이었다. 기본 pytest 임시 폴더의 기존 권한 문제를 피하도록 새 프로젝트 내 `--basetemp`를 지정했으며 명령과 옵션을 근거 JSON에 남겼다. 실패 원본과 과거 집계를 덮어쓰지 않았으며, 새 실행기와 입력을 별도로 동결했다.

## 발견한 제품 결함의 수정

누락된 파일도 등록 원문 상태 집계에 남기고, 명시한 source ID 또는 전체 검색 범위 안의 등록 missing 파일을 재관찰하도록 수정했다. 돌아온 파일은 현재 바이트와 revision으로 검색된다. 최초 등록부터 파일이 없던 경우도 처리한다. 읽기 전용에서는 같은 바이트가 복원돼도 저장 상태를 바꾸지 않고 미동기화 사실을 `partial`로 표시한다.

원문 복원 수정은 `src/jev_context/context.py`와 `sources.py`에 한정했다. 새 제품 회귀 12개와 고정 숨은 검사 13개, 공개 검사 13개가 통과했다. 26일 수정 직후 실제 SDK stdio MCP 두 서버로 누락·복원·일반/ID 검색·과거 원문 보존을 검증한 30개 확인이 모두 통과했다 (`.local/resume-20260926/fix-live/report.json`). 이후 다른 세션의 함수 분리와 테스트 보강을 포함한 27일 평가에서는 전체 256개 통과·기존 Windows symlink 권한 조건 1개 제외를 관측했다.

기존 `workspace_status`가 최대 2,000개 등록 파일을 관찰할 때의 시간 제한과 관찰 상한 표시는 이번 결함 수정의 범위에 추가하지 않았다.
