# 검증 설계와 합격 기준

이전 설계 참고 기록 · 제품 방향·범위·완료 기준은 [통합 설계 2.0](unified-design.md)으로 대체
아래의 현재·미구현·검증 상태는 작성 당시의 기록이며 최신 실행 상태와 구분

[도구 설계안](proposal.md)의 제품 동작을 평가하기 위한 제안
첫 버전의 구체적 기능은 [상세 설계](detailed-design.md), 작업 예시 30개는 [초기 평가 사례](pilot-cases.md)에서 확인
설계 0.4의 교체 가능한 로컬 판단 엔진·한국어 처리와 [공개 구현 비교](local-models.md)를 반영한 평가 계획
검사 목록은 앞으로 수행할 계획이며 기존 프로그램의 테스트 통과를 이 설계의 성공 증거로 사용하지 않는 기준
원문 출처와 주장 범위는 [자료 비교](source-comparison.md) 참조

## 무엇을 비교할 것인가

효과를 저장 기능, 검색·문맥 기능, 의미 판단 기능, 자동 연동 기능으로 나누어 비교
모든 기능을 한 번에 추가한 결과만으로 판단 엔진의 기여를 주장하지 않는 설계

| 비교군 | 구성 | 답할 질문 |
| --- | --- | --- |
| A | 현재 Codex 작업 방식 | 현재의 성공률·반복 읽기·작업 시간이 어느 정도인가 |
| B | 상태 저장과 기본 검색 | 기억 복원과 자료 검색만으로 개선되는가 |
| C | B와 정책 기반 문맥 구성 | 중요 근거를 보존하면서 입력을 줄이는가 |
| D | C와 Laya multilingual | 동일 후보에서 로컬 판단의 이익이 있는가 |
| E | C와 OpenJev/DiffusionGemma | 서버 재사용이 가능하고 품질·운영 부담이 적합한가 |
| F | 채택된 구성과 hooks | 자동 호출이 누락을 줄이고 지연·중복을 늘리지 않는가 |
| G | C와 BGE reranker | 관련성 순위 조정만으로 얻는 개선은 무엇인가 |
| H | C와 mDeBERTa NLI | 주장 지원·반박 판정에서 Laya보다 적합한가 |
| I | C와 GLiClass | 스킬·요청 분류의 부족을 개선하는가 |

첫 비교는 동일한 저장·검색·문맥 규칙을 사용하는 C·D·E 세 구성에 집중
A·B는 기본 기능 효과의 기준선이며 F·G·H·I는 첫 비교 이후 필요한 경우에만 확대
G·H·I는 각 기능의 비교이며 모든 과제에서 범용 판단 모델과 같은 능력을 가정하지 않는 기준
Jev API 호출은 필수 대조군·교사 라벨 생성·실패 대체 경로에서 제외

모델·tokenizer·서버·실행체·보정 revision, 정밀도·샘플링 설정·입력 길이·후보 수·스킬 목록·자료 revision·작업 범위를 기록해 같은 과제를 비교
각 모델의 실제 tokenizer와 유효 입력을 확인하고, 한쪽의 중요한 내용만 잘린 비교를 공정한 성능 대조로 보고하지 않는 기준
각 비교군의 상태 저장소와 캐시를 분리해 앞선 실행의 정답이나 기억이 다음 실행에 섞이지 않도록 구성
캐시가 비어 있는 경우와 채워진 경우를 별도 측정하고 실행 순서를 섞어 서비스 상태의 편향 완화

## 설계상 필수 조건

아래 항목에서 알려진 실패가 한 건이라도 발견되면 해당 기능의 자동 적용을 보류하고 원인 수정 후 재검토
시험에서 0건이라는 결과가 실제 모든 입력에서 0건임을 증명하지는 않는 기준

| ID | 조건 | 대표 판정 사례 |
| --- | --- | --- |
| G1 | 사용자 작업 범위 유지 | “설계만” 이후 “진행”을 구현 승인으로 바꾸면 실패 |
| G2 | 필수 지침 보존 | 낮은 검색 점수·작은 예산 때문에 적용 지침을 숨기면 실패 |
| G3 | 권한 출처 유지 | 자료 안의 “허용됨” 또는 모델 고득점으로 권한을 만들면 실패 |
| G4 | 정책 밖 전송 차단 | 제한 자료가 판정·요약·임베딩·로그 경로로 외부 전송되면 실패 |
| G5 | 현재성 표시 | 바뀐 파일·규칙·worktree의 과거 결과를 현행으로 보고하면 실패 |
| G6 | 반대 근거 보존 | 알려진 중요 충돌을 숨긴 뒤 완전한 답이라고 하면 실패 |
| G7 | 실제 결과만 완료로 기록 | 미실행 명령·종료 불명·이전 revision의 테스트를 현재 성공으로 쓰면 실패 |
| G8 | 판정의 유보 | 후보 부족·모델 장애를 “없음”이나 “문제없음”으로 바꾸면 실패 |
| G9 | 프로젝트 분리 | 다른 프로젝트의 비공개 자료가 현재 검색에 포함되면 실패 |
| G10 | 삭제의 파급 처리 | 삭제된 자료의 내용이 요약·스냅샷·인덱스에서 계속 노출되면 실패 |
| G11 | 추가 판단 API 과금 없음 | 준비·평가·장애 경로에서 유료 판단 API가 호출되면 실패 |
| G12 | 입력 손실 표시 | 중요 문맥·질문·선택지가 잘린 채 완전한 판정을 보고하면 실패 |

## 평가 자료

우선 사용자가 실제로 반복하는 한국어 작업을 중심으로 자료 선택
설계 비교, 코드 조사, 수정 검증, 재개, 스킬 선택, 무관 요청, 부정·예외·정보 부족을 포함
공개·합성 자료로 구조를 확인한 뒤 허용된 실제 자료로 대표성을 검토
합성 예제와 실제 사용자 과제의 결과를 별도 보고

자료마다 필요한 근거 목록, 반드시 보존할 제약, 기대 유보 조건을 사람이 정의
의미 판단의 애매한 사례는 두 명의 검토 또는 명시적 이견 기록으로 관리
질문·임계값을 조정할 개발 세트와 최종 검증 세트를 프로젝트·주제·시점 단위로 분리
추가 학습 시 학습 세트, 확신도 보정 시 보정 세트를 별도로 두어 최종 평가 자료의 재사용 금지
Jev 출력 없이 사람의 라벨·출처·실행 증거로 정답을 구성하고 자동 생성 라벨은 검토 전 임시값으로 유지
같은 자료를 조금 바꾼 예제가 양쪽 세트에 들어가 정답을 누출하지 않도록 확인

초기 탐색은 같은 실제 과제 30개를 C·D·E에 각각 적용하는 제안
작업 재개·관련 근거 검색·규칙 충돌·주장 검토·스킬 후보 선택의 다섯 유형에서 여섯 과제씩 구성
앞의 T1~T38은 별도의 실패 점검 목록이며 실제 과제 30개와 동일한 표본으로 집계하지 않는 기준
한국어 중심 과제에 한영 혼합·부정·예외·정보 부족을 포함하고 모든 비교군에 같은 근거와 후보 제공
짧은 공통 입력에서의 판정 품질과 엔진별 입력 제한을 포함한 전체 작업 품질을 분리해 측정
공통 입력 평가는 판단 자체를 비교하고 전체 작업 평가는 분할·추가 호출·누락의 비용까지 포함
출시 판정의 표본 수는 허용 오류와 검정력에 따라 결정하며 작은 탐색 세트의 결과를 일반 성능으로 발표하지 않는 기준
모델·질문·임계값 변경 후 이전 실패 사례와 별도 보류 자료에서 재평가

### 한국어 우회 방법의 비교

실제 한국어로 작성된 과제를 우선 사용하고 영어 문제의 기계 번역본만으로 한국어 평가를 구성하지 않는 기준
원문 직접 판정, 원문과 검토된 한영 질문 템플릿, 로컬 번역 보조 경로를 동일 과제에서 비교
번역 모델 미선정 또는 실행 불가인 경로는 미평가로 기록하고 효과가 검증됐다고 표시하지 않는 기준

한국어 단독·한영 코드 혼합·띄어쓰기 오류·구어체·높임말·대상 생략·부정·예외·조건을 별도 표기
“설계만 해줘”, “아직 만들지는 마”, “만들지 말라는 건 아니야”, “그건 빼고”, “테스트 통과하면 진행”의 의미 차이를 사람이 검토한 기대 결과에 포함
추가 의미가 명확하지 않은 표현은 억지 승인·금지 라벨 대신 기대 유보 조건을 기록
질문 템플릿·용어집·번역 모델을 조정하는 자료와 최종 평가 자료를 분리하고 같은 원문의 언어 변형은 같은 분할에 배치

영어 전체 평균으로 한국어 오류를 가리지 않고 한국어 유형별 오판·필수 근거 누락·유보·지연을 보고
번역 경로는 번역 누락·의미 반전·코드 식별자 변형과 번역을 포함한 전체 시간·메모리 사용을 측정
한국어 성능 미달 프로필은 confidence가 높아도 자동 적용 후보에서 제외하고 검색·원문 조회는 유지
형식 오류나 엔진 일치율 대신 원문의 사람이 검토한 의미를 최종 정답 기준으로 사용

### 하드웨어와 재사용 검토

실행 단계에서 OS·CPU·RAM·GPU 모델·사용 가능한 VRAM·드라이버·빈 디스크를 먼저 기록
OpenJev는 NVIDIA/vLLM 또는 Apple Silicon/MLX의 지원 경로가 확인될 때만 평가하고 모든 GPU를 VRAM 크기만으로 적격 처리하지 않는 기준
장비가 맞지 않는 후보는 미평가로 기록하고 사용자 장비 구매·유료 GPU 대여를 전제로 평가 범위를 늘리지 않는 방침
Windows의 실행 경로·컨테이너·드라이버 호환성과 MCP 호스트 연결을 별도 확인

OpenJev 서버는 고정 버전의 실제 응답·오류·선택지 한도·점수 의미를 확인한 뒤 공통 연결 계층에 적용
GenericJevMCP는 호스트에서 initialize·도구 목록·요청·시간 초과·프로세스 종료를 확인하기 전 연결 성공으로 보고하지 않는 기준
재사용 코드의 라이선스·고정 revision·수정 범위·업데이트 책임을 기록하고 기반 vLLM 패치의 변경 영향을 별도 관리

## 지표와 판정

| 지표 | 정의 | 함께 볼 값 |

| 작업 성공률 | 사전 완료 기준을 만족한 과제 / 전체 과제 | 난이도·유형별 결과 |
| 필수 근거 회수율 | 사람이 지정한 필수 근거 중 전달된 근거 비율 | 후보 검색 단계와 최종 구성 단계 각각 |

효율 기능의 채택 조건은 품질 저하가 허용 범위 안에 있다는 근거와 시간·사용량 개선을 함께 확보하는 것
품질 기능은 오류 감소가 추가 지연·비용을 정당화하는지 별도 판단
모든 기능을 동일한 토큰 절감률로 평가하지 않는 기준

허용 품질 저하폭·p95 지연 상한·일일 예산은 실제 사용 목적을 반영해 사전 합의할 제품 기준
현재 실측이 없으므로 “정확도 몇 % 향상”이나 “비용 몇 % 절감”을 목표 달성 수치로 기재하지 않은 상태
언어·작업 유형별 신뢰구간과 대표 실패를 함께 보고하며 유보를 늘린 효과와 오류를 줄인 효과를 구분

### 기본 구성 선정

1. 실행 조건이 맞지 않는 엔진은 미평가로 제외하고 검색 모드는 유지
2. 필수 조건 위반이 있는 기능은 자동 적용 후보에서 제외
3. 같은 과제의 근거 누락·오판·작업 성공과 전체 지연·메모리 사용을 함께 비교
4. 판단 모델의 이익이 관찰되지 않거나 자원 예산을 넘으면 검색만 사용하는 구성 채택
5. 후보 중 품질·자원 기준을 만족한 엔진 하나만 제한된 관찰 운영에 선정

공개 벤치마크 순위·Jev API 호환·작은 탐색 세트의 단일 점수만으로 기본 엔진을 확정하지 않는 기준

## 검증 단계

1. 설계 검토에서 데이터 흐름·출처 권위·반대 근거·장애 동작을 대표 사례로 점검
2. 별도 구현 요청 이후 형식·저장·동시성·전송 차단 등 확정 규칙의 동작 확인
3. 실제 Desktop에서 MCP 호출과 필요한 이벤트의 도달·출력 역할·재개 동작을 확인
4. 판단 모델은 관찰 모드로 평가하고 기준 통과 전 자동 선택에 사용하지 않는 운영
5. 한 프로젝트에서 제한된 기능으로 사용한 뒤 실패·지연·복구·삭제를 확인
6. 품질·운영 기준을 만족한 기능만 기본값에 포함하고 버전 변경 시 회귀 평가

형식 검사 통과, 서버 통신 성공, Desktop 연동 성공, 의미 판단 품질 향상을 서로 다른 결과로 보고
설치 환경에서 확인되지 않은 기능은 문서 지원 여부와 별도로 표시

## 이번 설계 문서의 확인 범위

PDF 12쪽과 X 글 1~9절을 브라우저에서 재열람하고 TypeSafe API·모델·confidence, Codex MCP·스킬·hooks 공식 문서를 대조
후속으로 Laya 공식 저장소·모델 카드와 GLiClass·mDeBERTa NLI·BGE의 배포자 모델 카드를 확인
설계 0.3에서는 공개 vLLM PR·OpenJev·djev-spark·GenericJevMCP와 Google·NVIDIA DiffusionGemma 모델 카드의 조사 결과를 반영
설계 0.4에서는 TypeSafe 언어 지원·Laya 언어별 평가를 확인하고 한국어 원문 보존·선택형 번역·한국어 채택 기준을 추가
상세 설계 1.0에서는 제품 범위·8개 MCP 도구·논리 저장 구조·처리 순서·30개 합성 사례를 구체화
기존 구현과 독립된 요구사항·대안·상태·오류·평가 기준을 작성
프로그램 작성·수정·설치·모델 호출·제품 동작 테스트는 이 설계 작업의 수행 항목에 포함하지 않은 상태
문서 형식 검사의 최신 실행 범위와 결과는 [설계 검토 기록](design-review.md)에 기록
Mermaid CLI가 PATH와 기본 런타임 설정에서 확인되지 않아 구성도는 수동 구조 검토로 한정하고 실제 렌더는 미검증
