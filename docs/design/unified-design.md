이 문서를 앞으로의 제품 방향·범위·완료 기준에 대한 단일 기준으로 사용

## 만들 제품과 사용 경험

한국어로 코딩 작업을 이어갈 때 **현재 상태에 맞는 근거·지침·도구 후보를 로컬 판단 모델로 고르고, Codex가 작업한 실제 결과까지 연결하는 조정기**
저장소를 기반으로 현재 요청마다 필요한 입력 묶음을 구성하고, 다음 행동의 후보와 그 판단이 성립하는 조건을 함께 제공하는 제품
목표는 필요한 근거를 놓치지 않으면서 반복 읽기·불필요한 선택·잘못된 작업 전달을 줄이는 것

예시 요청: “지난번 로그인 오류 조사 이어서 수정하고 테스트해줘”

1. 같은 작업의 목표·현재 허용 범위·남은 문제와 관련 파일의 변경 여부 확인
2. 오류 로그·현재 코드·관련 규칙·이전 실패를 검색하고 로컬 모델로 관련성과 반대 근거 판정
3. 필요한 발췌와 원문 위치를 묶고 현재 사용 가능한 검색·수정·테스트 도구 또는 스킬 후보 제공
4. Codex가 근거를 확인하고 작업 수행, 독립 조사 위임이 허용된 경우 해당 조사에 필요한 자료만 전달
5. 변경된 코드와 실제 테스트 결과를 연결하고, 검증하지 않은 조건을 남긴 채 다음 작업으로 이어가기

사용자에게 필요한 표시는 현재 목표, 선택한 근거, 충돌·누락, 다음 행동, 검증 결과
매번 저장 명령을 요구하지 않는 흐름을 목표로 하되 자동 연결이 확인되지 않은 환경은 수동 호출 상태로 명시
모델 없는 저장·검색은 비교 기준과 장애 대응 기능이며 **실제 모델 판단과 Desktop 연결을 확인하기 전에는 이 제품의 완성으로 판정하지 않는 기준**

### 출처에 없는 결론을 만들지 않는 원칙

한 자료가 특정 기능을 언급하지 않은 경우는 충돌이 아닌 범위 차이로 표시
아래 ‘결정’은 세 자료의 단순 합산이 아닌 이 제품을 위한 설계 선택
기존 사용 조건인 Codex Desktop, 한국어, 로컬 판단, 추가 유료 판단 API 없음은 원문 주장과 별도로 유지
이번 사용자 요청은 설계 재작성으로 해석하며 구현·모델 다운로드·설정 변경으로 확대하지 않는 범위

원문에서 모델에게 허용 분류를 묻는 것과 실제 권한을 모델만으로 부여하는 것을 구별하고 후자만 제외

P의 “Routing Does Not Work”라는 제목도 같은 문서 4쪽에서는 작은 문맥과 전체 비용을 조건으로 보완된 주장
P의 예시식 차이는 `3X - 5Y + 3Z`이며 같은 가정에서는 `5Y > 3X + 3Z`일 때 위임 경로가 더 저렴하다는 대수적 결과
이 식의 계수는 현재 요금이나 Codex 구독 비용으로 재사용하지 않고, 왕복 처리까지 측정해야 한다는 근거로만 채택

### 명시적으로 버리는 요소

- 모든 분기·파일·도구에 모델을 호출하는 일괄 설계와 매 턴 전체 자료 재판정
- 확신도를 정답률·사용자 승인·테스트 통과로 취급하는 처리
- 원문 삭제를 수반하는 압축, 반대 근거를 낮은 점수만으로 제거하는 처리
- Codex 내부의 숨은 추론 기록 수집, 내부 KV 캐시 제어, 기존 대화·전체 도구 목록 교체를 제품의 보장으로 설정하는 방식
- 특정 모델이 무조건 우수하거나 설치만으로 성능이 개선된다는 전제
- 브리핑·메일·항공 검색 등 원문 예시를 모두 별도 제품 기능으로 복제하는 확장
- 대시보드 배포·시각적 heatmap·모든 공개 도구 내장·재귀 에이전트 연구를 첫 제품에 포함하는 범위
- 모델의 낮은 점수만으로 불필요한 승인 질문을 추가하는 흐름

남길 중심 구조는 **공통 상태 → 제한된 후보 → 좁은 판단 → 제약을 지킨 선택 → 호스트 실행 → 관찰된 결과**

## 책임과 연결 범위

### 구성요소

현재 Python·SQLite 기반을 재사용 후보로 두고 책임에 따라 모듈 분리
새 저장 엔진·메시지 브로커·별도 웹앱을 필수로 추가하지 않는 구성

| 구성 | 입력과 책임 | 출력 |
| --- | --- | --- |
| 호스트 연결기 | MCP·Skill·검증된 이벤트로 현재 요청과 관찰 범위 수신 | 출처가 표시된 작업 입력 |
| 상태 저장소 | 작업·원문·revision·실행 보고·필수 완료 조건 보관 | 다시 조회 가능한 snapshot |
| 후보 검색기 | 파일·경로·식별자·기존 이슈·도구 목록 탐색 | 후보와 검색 범위·누락 정보 |
| 로컬 판단 서비스 | 관련성·주장 관계·후보 적합성·표현 단계 평가 | 검증 가능한 구조화 판정 또는 유보 |
| 문맥·행동 조정기 | 필수 정보·예산·현재 가용성 적용 | 문맥 묶음과 권고할 행동 |
| 검증·기록기 | 결과를 작업 조건·실행 대상과 연결 | 완료 증거, 남은 조건, 다음 상태 |

Codex는 계획·코드·설명·필요한 요약을 생성하고 기존 도구와 권한 체계 안에서 실행
우리 서비스는 원문·기록·추천을 제공하며 별도의 임의 명령 실행 프록시를 제공하지 않는 경계
실행을 권고하는 결과와 실행 권한을 부여하는 결과를 동일 필드로 표현하지 않는 계약

### Codex에서 약속할 기능

공식 [MCP 문서](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)의 로컬 STDIO 연결과 [Skill 문서](https://learn.chatgpt.com/docs/build-skills)의 단계적 로딩을 기본 연결 근거로 사용
설치된 설정·노출된 Skill만으로 실제 MCP 호출이나 자동 적용까지 검증됐다고 판정하지 않는 기준

| 기능 | 제품 책임 | 지원 확인이 필요한 부분 |
| --- | --- | --- |
| 작업 복원·근거 조회·판단 | MCP의 명시적 호출로 제공 | 실제 Desktop 도구 검색·호출·응답 |
| 재개·요청·변경 후 갱신 | 검증된 hooks로 갱신 신호와 묶음 ID 제공 | 호스트 버전·이벤트·신뢰·전달 결과 |
| 도구·스킬 추천 | 현재 목록 안의 후보와 상세 참조 제공 | 호스트가 제공하는 목록의 완전성 |
| 하위 작업 전달 | 별도 목적과 제한된 근거 묶음 작성 | 호스트의 위임 기능과 기존 사용자 허용 범위 |
| 생성 모델 선택 | 이용 가능한 선택지의 추천 | 실제 전환 권한·연결이 없으면 실행하지 않는 동작 |
| 전체 대화·KV 캐시 교체 | 이 제품 범위에서 제외 | 독립 실행기를 만들 때 별도 설계가 필요한 영역 |

호스트 기능은 `문서에 존재`, `현재 노출`, `시험 통과`를 각각 기록
`capabilities`에는 기능별 상태·관찰 시각·호스트 버전·증거를 저장하고 설치만으로 `시험 통과`를 부여하지 않는 규칙
지원하지 않는 기능을 숨기거나 모델 없는 모드로 성공 처리하지 않고 구체적 미지원 상태로 반환

### 자동 연결과 자료 권위

공식 [hooks 문서](https://learn.chatgpt.com/docs/hooks)를 근거로 이벤트 연결을 설계하되 전체 도구 경로를 관찰하는 장치로 가정하지 않는 기준
일부 이벤트의 추가 문맥이 developer 문맥에 들어간다는 계약 때문에 hook 출력은 고정 안내와 검증된 불투명 ID로 제한
원문·모델 판정은 MCP 데이터로 조회하고 높은 우선순위의 지시로 옮기지 않는 구조

| 계기 | 수행할 일 | 중복·실패 처리 |
| --- | --- | --- |
| 시작·재개 | 프로젝트·작업 연결 확인, 기존 snapshot 조회 | 연결이 불명확할 때만 대상 확인 |
| 새 사용자 요청 | 요청과 범위 갱신, 기존 묶음 유효성 확인 | 같은 turn/event ID 중복 억제 |
| 관찰 가능한 도구 완료 | 실행 결과 수집, 영향받는 자료만 갱신 | 완료를 관찰하지 못하면 `unknown` |
| 압축 전·후 | 저장된 결정과 근거 참조 보존·복원 | 호스트 대화의 무손실 보존 보장과 구분 |
| 작업 종료 | 필수 조건별 증거와 미해결 항목 정리 | 모델 점수로 미실행 검증 대체 금지 |

자동 수집 대상은 설정된 프로젝트·현재 연결 작업·허용 이벤트의 필드
사용자의 전체 대화 이력이나 홈 디렉터리 수집을 자동 연결의 전제로 삼지 않는 범위
불안정한 transcript 파일 형식에 의존한 수집은 기본 경로에서 제외
연결 누락 시 Skill을 통한 명시 호출로 복구하고 사용자에게 자동 연결 미완료를 표시

## 한 작업을 처리하는 규칙

### 상태 확보와 검색

1. 최신 사용자 요청과 호스트 지침을 읽고 `work_revision`과 현재 프로젝트·worktree 식별
2. 기존 결정·원문·완료 조건의 근거를 확인하고 제안과 확정 내용을 구분
3. 변경된 자료만 수집하고 각 자료의 내용 hash·관찰 시각·원문 위치 보관
4. 어휘·경로·코드 식별자 검색으로 후보 추출, 명시된 파일·필수 지침·미해결 충돌은 검색 순위와 별도로 확보
5. 현재 사용할 수 있는 도구·스킬·worker 목록을 조회 가능한 범위에서 갱신

작업 기록은 현재 요청을 이해할 근거이며 최신 명시 지시를 거부하는 고정 명령으로 사용하지 않는 원칙
“계속”은 기존 범위의 연속, “이제 구현해줘” 같은 명시 변경은 근거와 함께 범위 갱신
모호한 경우 먼저 주변 대화와 원문으로 해소하고 결과·권한에 영향을 주는 모호함만 사용자에게 확인

### 판단 서비스

검색·도구 추천·근거 검토마다 별도 모델을 적재하지 않고 선택한 프로필 하나에 좁은 질문을 전달
같은 입력만으로 답할 수 있는 질문은 묶고, 앞 판단 결과나 새로운 검색이 필요한 질문은 다음 단계로 분리

| 질문 종류 | 반환할 판단 | 후속 처리 |
| --- | --- | --- |
| 요청과 자료의 관련성 | 관련·무관·정보 부족 | 선택 후보의 순위와 추가 조회에 사용 |
| 주장과 근거의 관계 | 지지·반박·부분 지지·무관·불충분 | 반박과 근거 부족을 별도로 보존 |
| 현재 단계의 능력 적합성 | 후보별 적합·부적합·불충분 | 복수 후보 또는 해당 없음 허용 |
| 자료의 표현 단계 | 짧은 발췌·확장 발췌·원문·이번 전달 제외 | 보호 규칙과 실제 비용을 적용한 뒤 결정 |

질문에는 대상과 판단 기준을 완전하게 기술하고 ID 이름에 의미를 의존하지 않는 규칙
응답은 후보 ID·label·분포·점수 정의·질문 버전·엔진 프로필·입력 revision을 함께 기록
모델 출력은 허용된 ID·label, 유한한 수치, 해당 점수의 범위·분포 조건을 검사하고 잘못된 응답은 판정 실패로 처리
모델이 설명문을 반환하지 않으면 설명을 만들어 붙이지 않고 결정적 선택 사유 코드와 실제 근거 참조 제공
근거 참조의 존재는 코드로 검사하고 그 근거가 판정을 뒷받침하는지는 별도 검토 대상

`none`은 확보한 후보 중 맞는 것이 없다는 의미
후보 검색 누락·입력 잘림·모델 시간 초과·미지원 질문은 `insufficient` 또는 별도 실패 상태로 구분
모델 점수는 엔진별 정의를 보존하고 서로 다른 엔진의 값을 공통 정답 확률로 바꾸지 않는 계약
Choice·Score의 분포 집중도와 실제 정답률을 구별하는 근거는 [TypeSafe confidence](https://docs.typesafe.ai/confidence) 참조

### 문맥 구성

항상 먼저 넣을 항목은 현재 목표·범위, 적용되는 필수 지침, 관련 미해결 충돌, 이번 판단에 필요한 실패·반대 근거
모델은 남은 후보의 순위와 표현 단계를 조정하며 필수 항목을 숨길 수 없는 구조
판단 모델이 못 찾은 반대 근거도 존재할 수 있으므로 검색 범위 밖에 충돌이 없다는 보장은 제외

기본 표현은 원문 발췌이며 부정·예외·호출 관계가 걸린 경우 이웃 문단이나 관련 정의까지 함께 확보
생성 요약은 긴 자료에서 실익이 있고 Codex가 작성한 경우에만 사용하며 원문 위치·작성자·검증 상태를 표시
요약의 구조가 올바르거나 두 모델이 동의했다는 사실만으로 정확성을 확정하지 않는 기준

`hide`는 해당 묶음에서의 생략이며 원본 삭제와 별도
생략 목록에는 자료 ID와 생략 사유를 남겨 재조회 가능하게 구성
필수 본문이 예산에 들어가지 않으면 최소 필요량·부족 자료와 `insufficient`를 반환하고 완전한 묶음으로 보고하지 않는 처리

예산은 서비스가 반환하는 JSON 전체의 UTF-8 바이트와 호스트 토큰 추정을 따로 기록
본문뿐 아니라 근거 목록·생략 사유·도구 설명도 전송 예산에 포함하고, 원문 token 수를 전체 호스트 사용량으로 표시하지 않는 기준
긴 생략 목록은 별도 페이지로 조회하되 필수 충돌·불충분 상태는 첫 응답에서 확인 가능하게 구성
호스트의 잔여 문맥 예산을 관찰하지 못하면 설치 프로필의 반환 상한을 적용하고 실제 전체 문맥 크기는 미확인으로 표시
원문을 추가했을 뿐인 Desktop 경로에서는 과거 문맥을 제거한 것으로 계산하거나 입력 토큰 절감을 보장하지 않는 규칙

최종 묶음에는 사용한 자료·revision·범위·필수 지침·선택한 도구 후보·충돌·누락·판정 상태·유효성 조건 포함
파일 읽기 완료와 모델 결과 도착 사이에 원문·정책·작업이 바뀌면 판정 폐기 후 제한된 재준비 또는 불충분 반환
파일별 관찰을 저장소 전체의 동일 시점 snapshot으로 표현하지 않고, 고정 commit·별도 snapshot이 확보된 경우에만 해당 수준을 선언

### 도구와 스킬

공통 능력 목록에 ID·짧은 설명·적용 조건·읽기/쓰기 성격·가용 상태·상세 명세 참조·revision 보관
모델에는 현재 허용되고 가용한 후보만 전달하며 실행 직전 가용성과 revision을 재확인
기존 호스트의 도구 검색과 Skill 로딩을 재사용하고 독립적인 전체 목록 수집을 필수로 추가하지 않는 구성

사용자가 지정했거나 호스트 지침상 필수인 Skill은 모델 순위로 탈락시키지 않는 규칙
스킬을 읽어야 적용 조건이 확정되는 경우 상세 지침을 먼저 확인한 뒤 후보 판단 갱신
도구 선택은 호출 자체가 아니며 자유 형식 인수는 Codex가 작성하거나 검증한 원문 값을 코드로 복사
schema 일치·필수 인수·프로젝트 범위는 코드가 검사하고 기존 호스트의 권한 처리는 그대로 적용

### 위임과 결과 합류

위임 허용 범위 안의 독립 조사·검토부터 대상으로 설정
새 Codex 작업 생성과 내부 하위 작업을 구분하고 조정기 추천만으로 별도 대화를 만들지 않는 규칙
현재 호스트에서 실제 호출 가능한 worker가 없으면 전달 제안까지만 반환

전달 묶음에는 목표·입력 snapshot·담당 범위·금지된 변경·완료 조건·필수 근거·결과 형식 포함
같은 근거 검색 결과를 재사용해도 검토자는 추가 검색과 다른 반박 탐색 가능
쓰기 작업은 호스트가 제공하는 독립 작업 공간과 파일 소유 범위를 확보한 경우에만 병렬화
읽기 작업도 원문이 바뀌거나 CPU·GPU·파일 핸들을 경쟁할 수 있으므로 무제한 병렬 실행 제외

중복 키는 프로젝트·작업·목표·역할·입력 revision·대상 범위·회차로 구성
동일 키의 실행 중복은 억제하되 새 코드 revision의 재검토나 의도된 독립 검토는 허용
결과 합류 시 기준 revision과 최신 상태를 비교하고 오래된 결과를 현재 완료 증거로 자동 승격하지 않는 처리

위임 비교에는 자료 준비·모델 입력/출력·호스트 재검토·재시도·대기 시간을 모두 포함
사용량이 관찰되지 않으면 비용 절감을 추정하지 않고 관찰 가능한 지표만 제공
모델 전환 기능과 평가 근거가 없는 환경의 기본 행동은 현재 호스트 모델 유지

### 완료 검증

작업을 열거나 범위를 바꿀 때 완료 조건을 명시적으로 등록
각 조건에는 확인할 산출물·판정 방법·대상 revision·필요한 증거 종류를 연결
모델은 명세와 결과 사이의 의심 지점을 제안할 수 있지만 테스트 실행이나 파일 저장을 증명하지 않는 역할

조건별 상태는 `passed`, `failed`, `not_run`, `unknown`, `not_applicable`
`not_applicable`에는 범위 변경 또는 조건 해제의 근거가 필요하며 모델의 낮은 관련성만으로 부여하지 않는 규칙
필수 조건 중 실패·미실행·결과 불명이 있으면 작업 완료 증거는 미충족
주관적인 문서 품질은 검토자의 판정 근거로 기록하고 실행 테스트와 혼동하지 않는 표시

프로세스 시작·종료 코드·결과 파일·실행 대상 revision을 연결할 수 있을 때만 해당 실행 증거 등록
호스트가 말로 전달한 결과는 `agent_reported`, 서비스가 직접 읽은 파일·hash는 `service_observed`
호스트 이벤트의 독립 검증 경로가 구현·확인되기 전에는 검증된 provenance를 발급하지 않는 규칙

| Execution | 계획·시작·결과·대상 revision·provenance | 종료 관찰 없는 성공 선언 금지 |
| Handoff | 위임 목적·입력·소유 범위·회차·상태 | 중복 제출과 오래된 결과 구분 |

원문 보존은 허용된 자료를 의미하며 비밀 파일·전체 홈·숨은 추론까지 수집하는 뜻으로 사용하지 않는 기준
저장 정책과 로컬 모델 입력 정책, Codex로 반환할 정책을 구분
‘로컬 모델이 읽을 수 있음’만으로 Codex 반환을 허용하지 않고 목적과 대상에 맞는 정책 적용
자료 삭제 시 chunk·검색 인덱스·요약·판정·묶음·재시도 응답에서 노출 차단
이전에 Codex나 사용자가 받은 사본까지 회수할 수 있다는 보장과 물리적 저장 매체 소거 보장은 제외

### 도구 경계

현재 [실행 계약](../../src/jev_context/contracts.json)은 `1.0`이며 아래는 향후 `2.0`의 의미 계약 제안
이번 문서 작업에서 schema·서버·Skill·DB를 변경하지 않은 상태
도구 계약을 확장할 때 생산자와 소비자의 버전 협상·fixture를 먼저 작성하고 저장 형식 전환은 별도 검증

| 경계 | 역할 | 1.0 대비 설계 변경 |
| --- | --- | --- |
| `workspace_status` | 실제 연결·모델·기능별 준비 상태 | 기능 관찰과 실험 통과 증거 추가 |
| `work_open`, `work_record`, `work_inspect` | 작업·결정·실행 증거 관리 | 완료 조건 등록·조건별 판정 추가 |
| `source_sync`, `source_read`, `data_forget` | 수집·원문·삭제 | 소유 범위와 파생 참조 명확화 |
| `context_prepare` | 검색·판단·문맥 준비 | 유효한 로컬 판정 적용·보호·생략 명세 추가 |
| `capability_recommend` | 현재 도구·스킬 후보 평가 | 신규, 호스트 목록의 관찰 범위 필수 |
| `handoff_prepare` | 허용된 하위 작업의 전달 묶음 작성 | 신규, worker 실행과 별도 |

도구 입력에서 모델 실행 경로·원격 주소·프로젝트 루트·권한 정책을 변경하지 않는 기존 경계 유지
공통 응답에는 계약 버전·요청 ID·결과 상태·판단 수행 상태·provenance·부족 항목 포함
정상 결과·부분 결과·근거 부족·revision 충돌·기능 미지원·실행 오류를 구분
판정이 필요한 요청에서 모델이 빠졌으면 검색 결과가 있어도 판정 완료로 보고하지 않는 규칙

### 중복·지연·동시성

쓰기 작업의 `mutation_id`는 호출자가 같은 논리 작업의 재시도에서 유지하고 프로젝트·도구·ID 범위로 중복 판정
동일 ID·동일 입력은 저장된 결과 재조회, 다른 입력은 충돌 반환
동시 중복은 하나의 트랜잭션만 커밋하고 다른 호출은 진행 상태 또는 완료 응답 확인
1.0의 최소 30일 중복 기록 보존을 유지하며 실제 만료 이후에는 동일 키의 중복 방지를 보장하지 않는 경계

수신 확인·큐 저장·실행 시작·실행 완료를 각각 다른 상태로 기록
시간 초과와 취소는 실행 실패의 증거가 아니며 결과 불명인 외부 동작을 무조건 재실행하지 않는 처리
중단한 수집은 커밋된 항목 뒤에서 재개하고 삭제·정책 변경으로 무효화된 항목은 이전 요청 재생으로 복원하지 않는 규칙
여러 hook의 동일 이벤트도 안정적인 호스트 ID로 중복 억제하고, ID가 없어 합성을 사용할 경우 시간·관찰 범위와 충돌 가능성 명시

작업·원문 집합·정책·능력 목록·질문·모델 프로필 revision을 판정 캐시 키에 포함
자료 추가·삭제로 검색 후보가 바뀌면 기존 질의 문자열이 같아도 재검색
모델 실행 동안 DB 쓰기 잠금을 유지하지 않고 결과 커밋 전에 revision 재검사
순서가 뒤집힌 결과는 과거 관찰 기록으로만 보존하고 최신 결정을 덮어쓰지 않는 처리

버전 1 소비자에 새로운 enum·필수 필드를 조용히 보내지 않고 `2.0` 협상 실패 시 기존 기능만 노출
새 DB migration은 백업·복원·구버전 읽기 거절을 포함해 시험한 뒤 적용
공유 발췌의 소유권을 알 수 없는 기존 자료는 추정해서 삭제하지 않고 명시적 이관 대상으로 남기는 결정

## 로컬 모델과 자원

### 모델의 자리

로컬 판단은 완제품의 핵심 기능으로 유지하고 저장·검색과 독립적으로 교체 가능한 프로필로 구성
검증 실패를 이유로 판단 없는 제품을 같은 이름의 완료 상태로 바꾸지 않는 기준
모델 미준비·장애 시 검색은 계속 제공하되 `judgment_unavailable`과 적용하지 못한 기능 표시

| 후보 | 재사용할 부분 | 선택 전 확인 |
| --- | --- | --- |
| [OpenJev / DiffusionGemma](https://github.com/razorback16/openjev) | 기존 로컬 판단 서버 | 실제 장비·실행체·tokenizer·한국어 품질 |
| [Laya multilingual](https://github.com/NandhaKishorM/laya) | 경량 로컬 판단 작업자 | 짧은 입력 한도·선택지 잘림·한국어 부정과 예외 |

OpenJev 우선 검토와 Laya 비교 후보라는 기존 방향 유지, 현재 장비에서의 승자 미선정
OpenJev의 API 호환성은 Jev와 동일한 판단 품질을 의미하지 않는 기준
상류 저장소가 제공하는 호스팅 서비스·무료 체험·자동 checkpoint 라우팅은 이 제품의 로컬 단일 프로필 구성과 구분
런타임에는 미리 준비한 로컬 파일만 사용하고 유료 또는 원격 무료 모델로 자동 전환하지 않는 정책

상태는 `unprepared → prepared → shadow → evaluated → active`, 장애·과부하 시 `degraded`
`shadow`는 판정을 비교 기록만 하는 상태, `active`는 검증된 과제에 한해 선택에 반영하는 상태
한 과제를 통과한 프로필을 다른 질문·언어·입력 길이에 자동 확대하지 않는 규칙
가중치·서버·tokenizer·질문·정밀도·샘플링 설정이 바뀌면 영향받는 평가와 캐시 갱신

### 입력과 한국어

실제 tokenizer와 포장 형식으로 원문·질문·선택지 전체 길이를 계산
입력 초과는 SDK 내부의 조용한 잘림에 맡기지 않고 후보 축소·구조적 분할·불충분 반환 중 선택
각 조각의 판정을 평균해 전체 근거 충분성을 확정하지 않고 관계를 확인할 단계 유지

원문은 한국어 그대로 보존하고 질문도 한국어를 기본 실험군으로 구성
검토한 영어 질문·한국어 원문 조합을 비교할 수 있으나 별도 번역 모델은 첫 제품의 필수 구성에서 제외
“안 해도 돼”, “하면 안 돼”, “그건 빼고”, “일단 그렇게”와 코드·영어 식별자가 섞인 사례를 구분해 평가
다국어 지원 표기·영어 평가·일본어 예시를 한국어 정확도 보증으로 대체하지 않는 기준

### 처리 예산과 실패

아래 값은 이전 설계에서 가져온 초기 시험값이며 실제 장비 결과에 따라 조정할 설정
낮은 지연을 맞추기 위해 중요한 근거를 잘라내는 선택은 제외

| 항목 | 초기 시험값 | 초과 시 |
| --- | --- | --- |
| 문맥 준비 | 최대 5초 | 확보 범위와 부족 항목 반환 |
| 모델 판정 | 남은 예산 중 최대 2초 | 유보, 같은 요청의 무한 재시도 금지 |
| 작업 복원 | warm p95 500ms 목표 | 측정값과 목표 미달 공개 |
| 쓰기 잠금 대기 | 최대 1초 | `busy`, 동일 mutation으로 재조회 |
| 모델 실행 | 프로필 1개 상주 | 중복 적재·자동 모델 교체 차단 |
| 준비 단계 | 대화 요청과 별도 | 다운로드·cold loading 상태 명시 |

후보 수·최대 파일·저장 예산은 설치 프로필에 기록하고 평가 시 고정
시간 초과 뒤 실제 모델 처리가 남아 있으면 종료 확인 전 다음 요청을 누적하지 않는 구성
모델 오류는 검색으로 저하 가능하나 DB 실패·공개 정책 실패를 정상적인 빈 검색 결과로 처리하지 않는 원칙
성능 측정에는 모델 RAM·VRAM·cold 시작·반복 요청·동시 접근을 포함하고 작은 합성 예제의 warm 시간을 제품 지연으로 보고하지 않는 기준

## 평가와 제품 완료 기준

### 무엇을 비교할지

호스트 모델·추론 설정·프로젝트 snapshot·요청·시간 제한을 맞춘 비교
각 비교군의 작업 기억과 캐시를 분리하고 실행 순서를 섞어 이전 정답의 누출 방지

| 비교군 | 확인할 효과 |
| --- | --- |
| E0: 기존 Codex 흐름 | 현재 작업 성공·자료 읽기·시간 기준선 |
| E1: 저장·검색·보호 규칙 | 기록과 검색 자체의 이익 |
| E2: E1 + Laya | 로컬 의미 판단의 추가 이익 |
| E3: E1 + OpenJev | 다른 로컬 프로필의 추가 이익 |

장비상 실행할 수 없는 비교군은 `not_run`으로 남기고 성능 열위로 판정하지 않는 기준
질문·기준 조정용 데이터와 최종 평가 데이터를 분리하고 사람이 확인한 정답·필수 근거·허용 대안을 먼저 고정
실제 한국어 작업 30개는 탐색 시작점이며 기존 합성 사례 30개를 실제 평가로 재명명하지 않는 규칙
출시 판단에는 별도 보류 사례를 사용하고 오류율·표본 수·신뢰구간·유보율을 함께 보고

### 실패가 보이지 않도록 점수를 만들지 않는 평가

| 대상 | 지표 | 나란히 봐야 할 값 |
| --- | --- | --- |
| 검색 | 필수 근거 회수율, 반대 근거 회수율 | 검색 범위·후보 밖 정답 |
| 문맥 선택 | 잘못 생략한 필수 정보 수, 전달량 | 원문 재조회·복구량 |
| 도구·스킬 | 적합 선택과 불필요 사용 | 후보 누락·해당 없음·유보 |
| 실행 결과 | 과제 성공, 범위 위반, 허위 완료 | 실제 검증 증거와 revision |
| 모델 | 과제별 오류와 고확신 오답 | 자동 적용 비율·유보율 |
| 총효율 | 전체 시간·실제 관찰 사용량 | 판단 오버헤드·재시도·사람의 확인 시간 |

모델 도입 가치는 E2/E3과 E1 비교로 확인하고, 제품 전체 가치는 E2/E3과 E0 비교로 확인
탐색 단계에서는 과제별 성공·실패 내역을 먼저 보고하고 단일 평균으로 중요한 실패를 숨기지 않는 기준
활성화 기준은 필수 정보 누락·허위 완료·범위 위반의 신규 회귀 0건과, 사전 선택한 품질 또는 총효율 지표의 개선
전체 과제 성공의 악화를 유보율 상승이나 쉬운 사례만의 높은 정확도로 가리지 않고 기준선과 함께 판정
실제 판단 적용 사례와 적용 비율을 보고하며 모든 결과를 유보한 프로필은 활성화 평가 통과에서 제외
0건은 관찰한 평가 세트에서의 결과이며 현실의 오류 확률 0이라는 주장과 구분
개선 폭·허용 지연은 탐색 후 최종 보류 평가 전에 고정하고, 평가 후 유리한 기준으로 바꾸지 않는 절차
추가 이익을 확인하지 못한 프로필은 비활성 유지하며 ‘모델 기능 평가 미통과’로 보고

### 핵심 반례

다음 사례는 설계 확인 항목이며 이번에 실행한 제품 시험 결과는 아닌 상태

| 사례 | 요구하는 결과 |
| --- | --- |
| 낮은 관련성의 문서 마지막 줄에 금지·예외 | 보호 또는 원문 확장, 조용한 생략 금지 |
| 높은 점수의 주장과 반박 문서 동시 존재 | 양쪽 근거·관계 표시, 평균으로 충돌 제거 금지 |
| 질문과 선택지가 길어 입력 한도 초과 | 잘림 전에 감지하고 불충분 반환 |
| 판정 중 파일·목표·도구 목록 변경 | 과거 판정으로 현재 선택 확정 금지 |
| 적합 스킬이 후보 목록에 없음 | 검색 누락과 모델 오답 구분 |
| 도구 결과에 권한 위조 문장 포함 | 데이터로 취급, hook의 고권한 지시로 반사 금지 |
| 저장 성공 응답 유실·동일 요청 재전송 | 한 번 기록, 같은 mutation으로 결과 조회 |
| 실행 시작 후 연결 끊김 | 완료 불명, 무조건 반복 실행 금지 |
| 새 commit에서 같은 이름의 검토 요청 | 새 snapshot 검토 허용 |
| 공유 검색이 관련 파일을 놓침 | 검토자별 추가 검색 허용 |
| 모델 중단·원격 키 존재 | 로컬 검색 저하, 외부 모델 호출 없음 |
| 삭제한 원문을 과거 packet으로 조회 | 내용 반환 차단·무효화 표시 |
| 테스트 보고만 있고 실행 증거 없음 | 보고됨과 검증됨 구분 |
| 자동 이벤트 호출이 빠짐 | 명시 복구 가능, 자동 완료 주장 금지 |

## 구현 순서와 현재 코드의 위치

### 다음 구현에서 만들 단위

다음 표는 설계에 따른 향후 작업 순서이며 이번 요청으로 수행한 작업 목록과 구분

| 단계 | 산출물 | 다음 단계로 넘어갈 증거 |
| --- | --- | --- |
| V0 연결 검증 | 호스트 기능표와 실제 MCP·이벤트 시연 | 동일 작업 복원·호출·전달을 Desktop에서 관찰 |
| V1 핵심 흐름 | 실제 로컬 모델로 검색 → 관련/반박 판단 → 묶음 → Codex 사용 | 한국어 원문 추적·판단 수행·효과 비교 |
| V2 선택 범위 | 현재 도구·스킬 후보 추천과 원문 단계적 조회 | 후보 누락·가용성 변경·해당 없음 평가 |
| V3 결과 연결 | 완료 조건·실행 증거·허용된 위임 묶음 | 실제 결과 검증·오래된 결과 격리 |
| V4 통합 평가 | 재개·중단·변경을 포함한 E0~E3 비교 | 품질·총효율·유보율과 실패 사례 공개 |

자동 이벤트를 지원하지 않는 환경은 V0에서 지원 수준을 명확히 표시하고 명시 호출 프로필로 별도 평가
완제품 판정은 V1~V4의 실제 모델·호스트 흐름까지 확인한 뒤 가능
V0~V1에서 모델 또는 호스트 연결이 불가능하면 해당 환경의 미완료 조건으로 남기고 저장소 테스트로 대신하지 않는 기준

### 재사용·보완·신규

현재 코드와 [구현 보완 기록](../implementation-notes.md)을 기준으로 한 이행 계획
기존 테스트 결과는 기존 계약의 근거이며 설계 2.0의 제품 효과 증명으로 사용하지 않는 범위

| 분류 | 대상 | 이유 |
| --- | --- | --- |
| 재사용 후보 | SQLite·원문 revision·검색·경로 정책·중복·삭제·MCP | 새로운 판단 흐름에도 필요한 기반 |
| 보완 | 문맥 구성·모델 어댑터·프로필·Skill | 실제 모델 결과 적용과 호스트 피드백 필요 |
| 우선 해결 | OpenJev 입력 tokenizer 연결, 실제 Laya 준비·평가 | 어댑터 존재와 실제 판정을 구분하는 핵심 간극 |
| 신규 | 능력 목록·추천, 완료 조건, 위임 묶음, 검증된 이벤트 연결 | 1.0의 저장·검색 범위를 넘어서는 제품 동작 |
| 제외 | 전체 하네스 교체·KV 제어·임의 실행 프록시 | Desktop 보조 제품의 제어권과 목적 밖 |

기존 구현을 먼저 모두 버리거나 기존 도구 8개에 맞춰 제품 범위를 다시 축소하지 않는 결정
호환되는 기반은 유지하고 새로운 기능은 명시적 계약 버전과 검증으로 확장

## 남은 선택과 이번 설계의 확인 결과

가용 RAM·GPU, 실제 로컬 모델 프로필, Desktop hook 동작은 후속 환경 검증 항목
평가 전에는 OpenJev·Laya의 한국어 우열이나 최종 성능 수치 미확정
이 미확정 항목은 제품 목적을 바꾸는 이유가 아닌 실행 프로필·활성화 범위를 결정할 입력

이번 설계에서 확인한 내용은 세 원문 재열람, 7개 공통 항목 통합, 12개 쟁점의 처리 결정, 호스트 경계와 기존 코드의 간극
새 프로그램·모델 설치·추론·Desktop 실행 시험은 이번 작업에 포함하지 않은 범위
문서 형식·링크 검사는 별도 수행하며 통과 사실을 의미 판단 성능과 혼동하지 않는 기준
