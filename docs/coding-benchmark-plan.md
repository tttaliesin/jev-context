# 독립 코드 수정 비교 계획

단순한 근거 문자열 포함률을 넘어, 코드 변경 후 고정된 검사가 통과하는지 비교하는 소규모 개발 진단
기존 구현의 복사본에 결함을 하나씩 주입한 과제이며 실제 미해결 제품 버그나 사람이 검토한 heldout으로 표시하지 않는 기준

## 비교 과제

| 과제 | 주입 결함 | 성공 조건 | 수정 허용 파일 |
| --- | --- | --- | --- |
| JSON 입력 | 중복 키 검사를 건너뛰는 입력 파서 | 중첩 중복 키·비정상 숫자 거절, 정상 JSON·크기 경계 유지 | src/jev_context/cli.py |
| 도구 가용성 | 비가용 도구도 모델 후보에 포함 | 비가용 도구 평가·선택 제외, 필수 도구 누락과 정상 후보 처리 유지 | src/jev_context/coordination.py |
| 응답 예산 | 필수 근거를 선택 자료처럼 제거 | 필수 근거 보존 또는 명시적 insufficient, 전체 응답 예산 준수 | src/jev_context/budget.py |

과제당 모델 off와 shadow 관찰 문맥을 하나씩 제공하는 6회 실행
각 실행은 새 문맥의 동일 모델 보조 에이전트 하나, 동시에 최대 2개
사용자의 `보조 에이전트 6회 실행` 응답으로 해당 범위 승인 확인
현재 대화 이력·반대 조건의 문맥·원본 정답 구현·채점 자료를 에이전트 입력에 포함하지 않는 구성
작업별 로컬 디렉터리를 분리하고 지정된 구현 파일 하나만 변경 허용
이 경로 분리는 작업 지시와 사후 파일 hash 검사로 확인하며 OS 수준의 별도 가상머신 격리와 구분

## 검증 순서

1. 원본 복사본의 검사 통과와 결함 주입본의 실패 확인
2. 과제·문맥·검사·입력 파일 hash를 실행 전에 고정
3. 승인된 범위에서 같은 모델의 독립 보조 에이전트 6회 실행
4. 에이전트 종료 뒤 고정된 검사로 결과 검증, 허용 파일 밖 변경 시 해당 실행 무효 처리
5. 성공률·실제 경과 시간·문맥 준비 비용·관측 가능한 호스트 사용량 기록

보조 에이전트 사용 확인은 제공된 spawn_agent 도구의 명시적 위임 허용 요구에 따른 단계
보조 에이전트는 사람 검토자로 취급하지 않는 기준
현재 운영 설정은 shadow 유지, 합성 평가를 위해 human_reviewed 승격 보고서 생성 금지
호스트 입력 토큰이나 요금이 실제 사용 기록에 없으면 null 유지, UTF-8 바이트를 토큰이나 요금으로 환산하지 않는 기준

## 문맥과 측정 범위

두 조건 모두 같은 한국어 설계 문서 발췌 4개와 영어 작업 지시 사용
`off`는 원문만 전달, `observe`는 원문에 운영 v2-2의 관련성·표현 길이 판단 추가
한국어 원문을 영어로 번역하는 단계나 모델 판단에 따른 원문 제외·축약은 미적용
원본 정답 구현 대신 정책 문서만 모델 입력으로 사용

모델 판단은 실제 Modal 어댑터 호출로 수집하며 전체 `context_prepare` 검색·예산 경로의 종단 비교와 구분
첫 RTX-PRO-6000 요청의 대기열 적체로 해당 앱 종료 후 같은 모델·지시문의 평가용 B200 임시 세션 사용
평가용 profile·runtime hash와 운영 profile을 분리하고 GPU 유형 변경을 실행 기록에 보존
현재 shadow의 판단 제공 효과를 보는 진단으로, active 자동 선별의 압축 효율·일반 코딩 능력으로 확대 해석 금지
쉬운 결함 3개·조건별 단 1회이므로 성공률 차이가 없어도 모델 효과 부재를 일반화하지 않는 범위
경과 시간은 도구 호출로 확인한 호스트 관측값이며 동시 실행·큐·캐시·실행 순서의 영향 포함

## 재현 절차

저장소 루트의 기존 Python 환경 사용, 새 출력 디렉터리 지정 필요

```powershell
.venv\Scripts\python.exe -m scripts.coding_benchmark prepare --directory .local/coding-benchmark-new
```

같은 작업의 Modal 세션 준비 후 원문·판단·검사 hash 고정

```powershell
.venv\Scripts\python.exe -m scripts.coding_contexts --directory .local/coding-benchmark-new --config .local/project.toml --work-id <WORK_ID>
```

승인된 독립 실행 종료 후 지정 과제 채점

```powershell
.venv\Scripts\python.exe -m scripts.coding_benchmark verify --directory .local/coding-benchmark-new --trial json-off
```

실패 결과도 기록 보존, 결과를 본 뒤 정답·검사·초기 입력을 수정해서 재채점하는 방식 제외
첫 준비에서 상위 pytest 설정이 원본 코드를 불러오는 문제를 발견하고 전용 설정·외부 conftest 차단으로 수정
상위 설정 오염을 재현한 회귀 검사에서 수정 전 실패·수정 후 통과 확인
