# Ollaya에서 실제 추가 학습까지 가려면

2026-09-28. [2차 계획](ollaya-tuning-plan.md)에서 정한 추가 학습 가능성·비용 검토다. 학습을 실행한 보고서는 아니다.

## 무엇을 튜닝한다는 말인가

Ollaya는 모델을 내려받고 실행하며 같은 API로 질문하는 프로그램이다. 실제 판단은 Laya나 decider 같은 모델이 한다. ‘Ollaya가 튜닝하기 편하다’는 말은 다음처럼 서로 다른 작업을 뜻할 수 있다.

| 방법 | 실제로 바뀌는 것 | 이번 프로젝트에서 한 일 |
|---|---|---|
| 질문·입력 조정 | 지시문, 선택지 설명, 전달하는 자료의 구성 | 2차에서 Laya 6개 구성과 decider 2개 구성 비교 |
| 확률 보정·보류 설정 | 점수를 해석하고 답을 받아들일 기준 | 1차 온도 보정, 2차 개발 자료에서 보류 기준 선택 |
| 모델 변경 | 판단하는 모델 자체 | Laya와 decider 0.8B 실제 비교 |
| 가중치 추가 학습 | 정답 사례를 학습해 모델 내부 수치를 변경 | 아직 실행하지 않음. 아래에서 준비 조건을 검토 |

`Modelfile`은 기존 모델에 질문·보정값 등을 묶어 이름을 붙이는 설정 파일이다. 이것만 작성한다고 모델이 새 지식을 학습하지 않는다. 필드를 재구성하거나 여러 답을 합치는 작업은 별도 코드가 필요하다. [Ollaya 공식 계약](https://ollaya.dev/docs/modelfile)

## 실제 학습 경로는 있다

Laya 제작자는 도메인 데이터에 맞춘 추가 학습을 권장하고, 데이터 구성부터 학습·온도 보정·평가·모델 저장까지 수행하는 [공식 노트북](https://github.com/NandhaKishorM/laya/blob/main/notebooks/laya_finetune_typed_decisions_2xT4_kaggle.ipynb)을 제공한다. 따라서 이번 설정 조정의 낮은 점수로 **추가 학습도 불가능하다고 결론 내릴 수 없다**. 다만 공식 예제의 데이터와 우리 한국어 작업 판단은 다르다. [Laya 학습 안내](https://github.com/NandhaKishorM/laya#fine-tuning)

공식 안내의 참고 실행량은 약 3만 질문·4 epoch·T4 2장으로 약 4~5시간이다. 이는 제작자의 조건이며 현재 PC의 소요 시간, 필요한 최소 데이터 수, 한국어 성능 개선 폭을 뜻하지 않는다. 공개 노트북의 보정 표본은 학습 항목에서 뽑는다고 명시돼 있으므로, 우리 실험에서는 학습·보정·최종 평가 자료를 분리해야 한다. 같은 출처에 있는 영어 모델의 개선 수치를 우리 모델의 예상 점수로 사용하지 않는다. [실행량과 보정 한계](https://github.com/NandhaKishorM/laya#fine-tuning)

## 다음 학습 실험을 구체화하는 순서

아래 수량은 이 프로젝트의 **제안하는 착수 목표**다. 검증된 최소 표본 수나 성능 보장은 아니다.

1. **판단 기준과 실제 자료를 먼저 정리한다.** 관련성·근거 관계·도구 적합성의 정답 기준을 정의하고, 우선 실제 업무에서 나온 600개 후보 사례를 검토한다. 같은 작업·문서·표현의 변형은 같은 그룹으로 묶는다. 합성 자료는 출처를 표시하고 사람이 검토한 실제 사례와 구분한다. 개인정보나 비공개 코드는 임의로 외부 학습 서비스에 올리지 않는다.
2. **새 평가 자료부터 잠근다.** 그룹 단위로 학습·개발·확률 보정·최종 평가를 분리한다. 기존 120개는 모두 공개된 진단 자료이므로 앞으로 새 최종 평가로 재사용하지 않는다. 사람이 정답과 중요 오류를 검토해야 한다. 특히 ‘작업 시작은 완료가 아님’, ‘한 범위의 성공은 전체 성공이 아님’, ‘사용 금지는 기능이 있어도 부적합’ 사례를 포함한다.
3. **소규모 실행으로 비용을 측정한다.** 정확한 multilingual 체크포인트와 학습 코드 revision을 고정하고 100 step 정도의 예비 실행에서 GPU 메모리·step 시간·손실 변화를 측정한다. CPU 추론 메모리로 GPU 학습 가능 여부를 추정하지 않는다. 확보된 GPU와 측정치를 바탕으로 본 학습 시간과 비용을 산출한다.
4. **하나의 작은 학습 후보부터 비교한다.** 원래 모델과 동일한 입력 계약을 유지하며 학습한 후보를 개발 자료로 선택한다. 보정은 별도 보정 자료에서만 한다. 학습량을 늘릴지는 개발 곡선으로 결정한다. 최종 평가를 본 뒤 같은 평가 자료에 맞춰 다시 튜닝하지 않는다.
5. **Ollaya 반입을 별도로 검증한다.** 원래 학습 실행과 ONNX 등 변환 실행에서 동일 입력의 선택·확률·잘림 처리를 비교한다. 모델 hash와 라이선스를 보존하고, Ollaya 패키지로 만든 뒤 API 계약·메모리·해제 동작을 검사한다. 최종적으로 SemIf와 같은 새 평가에서 비교한다.

## 학습한 파일을 바로 Ollaya에 넣으면 되는가

확인한 Ollaya v0.7.3 변환 도구는 알려진 체크포인트 목록을 기준으로 내보내기와 registry manifest·blob 패키징을 구성한다. 임의의 학습 체크포인트를 `Modelfile FROM` 한 줄로 넣는 완성된 경로는 이번에 검증하지 않았다. 추가 학습 자체와 실행기에 반입하는 작업은 따로 견적을 잡아야 한다. 근거: 고정 버전의 [export.py](https://github.com/ollaya-dev/ollaya/blob/v0.7.3/convert/ollaya_convert/export.py), [package.py](https://github.com/ollaya-dev/ollaya/blob/v0.7.3/convert/ollaya_convert/package.py).

| 준비 항목 | 현재 판단 |
|---|---|
| 학습 방법 공개 여부 | Laya 공식 경로 확인 |
| 한국어 업무 정답 데이터 | 자체 진단 120개만 확보. 실제 업무·사람 검토 학습 자료는 미확보 |
| 학습 GPU·예상 비용 | 이번 CPU 추론 시험으로 판단할 수 없음. 예비 학습 측정 전에는 금액·시간 확정 불가 |
| 새 가중치 Ollaya 배포 | 변환 소스 확인, 임의 체크포인트의 변환·동등성·설치 미검증 |
| 이번 제품에 적용 | [2차 결과](ollaya-tuning-results.md)의 도입 기준에 따라 결정. 학습 성공을 선반영하지 않음 |

현재 권고는 질문 문구를 계속 늘리는 것보다 **사람이 검토한 업무별 정답 자료와 소규모 학습·변환 예비 실험을 다음 과제로 잡는 것**이다. 실제 GPU 학습과 모델 교체는 이번 계획의 실행 범위에 포함하지 않았다.
