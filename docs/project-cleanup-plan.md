# 프로젝트 잔여물·의존 관계 정리 계획

작성: 2026-09-27 · 기준 커밋: `8a10ef8` · 사용자 요청: “계획 문서로 만들고 계획대로 진행해줘”

## 목적과 범위

중단한 실험을 제품 실행 경로에서 분리하고, 실행 관측과 엔진 식별의 불필요한 의존 관계를 줄인다. 로컬 임시 생성물은 사용 여부와 경계를 확인한 뒤 정리한다. 기존 작업 DB, 등록 원문, 실패를 포함한 실험 결과, 현재 모델·환경, 실행 중인 프로세스는 보존한다. 선택하지 않은 엔진을 지원 중단한 것으로 간주하지 않는다.

## 실행 순서와 완료 기준

1. **현황 확정**: Git 상태, 실행 프로세스, 모델 프로필과 경로, 정리 후보의 크기를 확인한다. 접근 불가 항목은 측정값에서 구분한다.
2. **임시 생성물 정리**: `.t`의 종료된 검사 디렉터리와 `.local/startup-20260926`의 과거 생성 캐시를 대상으로 한다. 절대 경로가 저장소 안인지, junction/symlink가 없는지, 현재 설정·프로세스가 사용하지 않는지 확인한다. 삭제 전 파일 목록·크기와 남길 결과 기록을 `.local/cleanup-20260927`에 기록한다. 접근 제한이나 사용 중인 대상은 건너뛰고 결과에 남긴다.
3. **중단 실험 분리**: `src/jev_context/tool_hooks.py`를 `experiments/output_filter`로 이동한다. 실험 테스트도 함께 분리하고 실행 스크립트·문서 참조를 갱신한다. 실험은 명시적으로 검사할 수 있게 유지하되 제품 wheel과 기본 제품 테스트에 포함하지 않는다. 동결된 과거 벤치마크 입력은 수정하지 않는다.
4. **파일 저장 의존 정리**: 안전 경로·원자적 쓰기를 공통 파일 유틸리티로 분리한다. 실행 관측은 온보딩 모듈을 import하지 않고 자체 잠금을 사용한다. 온보딩의 기존 잠금·오류 계약은 보존한다. 잠금 경합과 기존 기록 보존을 검사한다.
5. **엔진 식별 범위 축소**: 공통 코드와 선택한 엔진의 실제 실행 코드만 식별값에 포함한다. 다른 엔진 변경은 식별값을 바꾸지 않고 해당 엔진·공통 코드 변경은 바꿔야 한다. 기존 프로세스·외부 세션·과거 평가 식별값은 새 식별값과 혼용하지 않는다. 모델 승격과 자동 실행은 하지 않는다.
6. **모델 선별**: 현재 및 보존 프로필, 변환 원본, 재현에 필요한 모델을 확인한다. 재생성 가능한 미사용 변환본만 명세·해시를 남기고 정리한다. 용도가 불명확하거나 현재 경로가 참조하는 항목은 보존하며 이유를 기록한다. 모델 원본과 지원 중인 다른 엔진의 가중치를 일괄 삭제하지 않는다.
7. **검증·반영**: 관련 회귀 검사 → 전체 Python 검사·별도 실험 검사 → Node 검사 → wheel 내용 검사 → 앱 빌드 순서로 확인한다. 한·영 README와 개발 문서에 구조 변경·검사 명령을 반영하고 결과 문서에 실제 회수량과 남긴 항목을 기록한다. 커밋·원격 반영 후 같은 커밋의 CI 결과를 확인한다.

## 유지하는 구조

Electron–Python 연결은 UI와 서비스 간 통신에 사용된다. 공유 모델 프로세스는 중복 로딩 방지에 사용된다. v1 계약은 v2 스키마 생성과 호환 검사에 사용되므로 이번에 제거하지 않는다. 연구 문서는 과거 근거로 유지한다.
