# Ollaya 튜닝·실행기 비교 계획

작성: 2026-09-28 KST. 기준 소스: `63c6a37`. 상태: **자체 검토 및 수정 완료, 진단 실행 확정**. [검토 기록](ollaya-evaluation-review.md).

실행 완료: [결과 및 유지 결정](ollaya-evaluation-results.md). 아래 기준을 실행 전에 정하고 그대로 평가했다.

## 목표와 범위

Ollaya의 질문·선택지·확률 보정이 한국어 작업 판단을 얼마나 개선하는지 실제 실행으로 확인하고, 현재 SemIf OpenVINO를 대체할 근거가 있는지 결정한다. [선행 조사](ollaya-research.md)를 바탕으로 모델 실행 부분만 비교한다. 작업 기억·원문 revision·Electron UI는 유지한다.

이번 튜닝은 질문 및 선택지와 temperature calibration이며 모델 가중치 학습이 아니다. 결과는 에이전트가 작성한 진단 사례에 한정한다. 사람 검토 평가나 실제 코딩 작업 효율을 입증하지 않으며 자동 추천 승격은 하지 않는다.

## 실행 순서와 산출물

1. **계획 검토:** 데이터 누출, 비교 공정성, 설치 격리, 재현성, 실패 처리, 종료 조건을 자체 검토하여 별도 문서에 지적과 수정 내용을 남긴다. 수정된 계획을 확정한 다음 설치·추론을 시작한다.
2. **사례·설정 고정:** 한국어 60개, 개발 30개와 최종 진단 30개로 분리한다. 각 집합에 relevance / evidence_relation / capability_fit 각 10개를 넣고 정답·근거·중요 오류 표시를 작성한다. 기본 질문과 한국어 간결 질문 두 후보를 추론 전에 고정하고 파일 SHA-256을 기록한다. 기존 평가 사례는 재사용하지 않는다.
3. **격리 준비:** 공식 v0.7.3 Windows CPU 배포를 `.local/ollaya-evaluation/`에 내려받아 공식 checksum과 대조한다. 모델 저장소·loopback 포트·로그를 분리하고 PATH·서비스·시작프로그램·MCP 설정은 변경하지 않는다. `laya:multilingual`만 준비하고 최대 상주 모델 1개를 사용한다. 바이너리뿐 아니라 다운로드한 manifest와 모델 blob hash도 기록한다.
4. **개발 비교·튜닝:** 개발 집합에서 두 질문 후보를 실행한다. 정답 수 최대, 중요 오류 최소, 동점이면 기본 질문 순서로 선택한다. 선택한 질문의 확률에 temperature grid `[0.5, 0.75, 1, 1.5, 2, 3, 4]`를 적용하여 개발 NLL 최소값을 선택한다. baseline 확률의 원래 보정 온도를 확인하고 합성하여 Modelfile의 절대 온도로 저장한다. 보정은 argmax 정확도를 바꾸지 않는다. 보류 임계값 `[0, 0.5, 0.6, 0.7, 0.8, 0.9, 0.95]` 중 개발 집합에서 수락 정확도 90% 이상·중요 오수락 0·수락 10개 이상을 만족하는 최저값을 선택한다. 없으면 전부 보류한다.
5. **최종 진단:** 선택과 보정값을 저장한 후 최종 집합에 기본 Ollaya, 선택 질문 Ollaya, 보정 Ollaya, 현재 SemIf를 실행한다. 결과를 본 뒤 재튜닝하지 않는다. SemIf는 같은 상태와 현재 제품 질문을 사용한다. 두 런타임은 순차 실행하고 각 모델 해제를 확인한다.
6. **계약·자원 검사:** 잘린 입력 거절, 명시적 로드/해제, 유휴 해제, 종료 후 프로세스 상태를 확인한다. 준비 시간과 추론 p50/p95, 프로세스 working set을 기록한다. CPU Laya와 GPU SemIf의 모델·장치 차이를 함께 표시한다. 요청당 실험 제한은 10초, 실제 제품 2초·6초 예산 충족률도 따로 표시한다. 오류·시간 초과는 정답률 분모에 남긴다. 실패한 요청을 몰래 재시도해 대체하지 않는다.
7. **판정·적용:** 최종 진단 정답률이 SemIf 이상, 중요 오류 0, p95 2초 이하, 계약 검사 통과를 모두 만족하면 외부 실행기 shadow 통합의 후속 후보로 채택한다. 하나라도 미달이면 현재 실행기를 유지하고 재현 가능한 실험 도구·Modelfile·결과를 적용한다. 작은 자체 진단만으로 제품 실행기를 교체하거나 기존 모델을 삭제하지 않는다. 정식 통합·승격은 별도의 사람 검토 사례와 전체 작업 효율 검증 이후 단계다.
8. **완료:** 비교 보고서, 재현 명령, 한계, 미실행 항목을 남기고 README 한영 링크를 갱신한다. 실험 계산·실패 처리 테스트 및 기존 검사 후 커밋·원격 반영한다.

## 측정과 중단 조건

검토 보완: temperature는 전체 세 목적이 공유하는 `choice:3-5` 버킷에 하나만 맞춘다. 반환 확률 반올림으로 인한 근사임을 표시하고 실제 파생 모델 응답과 대조한다. 원래 온도를 확인하지 못하면 calibration 적용은 실패로 기록하며 추정값을 배포하지 않는다. 임계값은 보정된 최대 확률에 적용하며 `insufficient_evidence` 선택은 항상 보류다. 준비 시간은 디스크 캐시 상태를 명시하고 첫 추론은 별도 표시한다. working set은 샘플 관측치이며 시스템 전체나 GPU 메모리의 정밀 peak로 주장하지 않는다. 시작 시 가용 RAM 4 GiB 미만이면 로드를 중단한다. 반복 지연 실험은 최종 사례 순서를 바꾸거나 선택을 다시 하지 않고 같은 고정 표본 3회를 사용한다.

중단된 실행은 누락 사례를 `not_run`으로 남겨 전체 분모와 실행된 수를 구분한다. 정상 실행과 결과를 섞어 재시도하지 않는다. localhost 전용 실행 도구는 공용망 endpoint를 거부한다. 실험 산출물에는 `promotion_eligible: false`를 고정한다.

정답률·목적별 confusion·중요 오류·보류율·수락 정확도·NLL·Brier를 보고한다. 모델 off는 호출 및 모델 메모리 0인 제어 상태이며 분류 정확도 값은 부여하지 않는다. 최소/최대 confidence 정의가 다른 런타임의 원래 점수를 직접 비교하지 않는다.

실험 시작 전 활성 모델 소유 프로세스를 확인한다. 다른 작업이 모델을 쓰면 강제 종료하지 않고 격리 가능한 검사만 수행한다. 다운로드·manifest 검증 실패, 모델 로드 실패, 남은 메모리 부족 또는 연속 3개 추론 오류가 나면 해당 실행을 중단하고 실패 증거를 남긴다. 다른 실행기 실험은 독립적으로 진행한다. 개인 대화·프로젝트 비밀은 외부 모델 서버에 보내지 않고 작성한 사례만 localhost에서 처리한다.
