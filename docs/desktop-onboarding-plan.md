# 앱 안에서 끝내는 프로젝트 설정과 Codex 연결

작성: 2026-09-27. 사용자의 요청: 초기 설정 UX 적용 계획을 문서화하고 그대로 구현한다.

## 목표와 범위

앱에서 폴더를 선택하고 새 프로젝트를 준비한 뒤, 변경 내용을 확인하고 Codex MCP·Skill을 설치한다. 같은 화면에서 통신 점검, 재연결 안내, 실제 확인 요청 수신, 설치 되돌리기를 제공한다. 기존 프로젝트도 상단 **Codex 연결**에서 이 흐름을 다시 열 수 있다.

현재 앱은 이 PC의 Python 환경을 사용하는 개발 배포다. 이번 범위는 프로젝트 설정과 연결 온보딩이며 Python·모델 가중치를 포함한 독립 설치 프로그램 제작은 아니다. Python을 찾지 못하면 앱에서 실행기를 다시 선택하고 재시도한다. 새 프로젝트는 모델 없이 시작하고, 설치·조회·점검이 GPU나 원격 모델을 시작하지 않는다.

## 근거와 적용

- [공식 MCP 안내](https://learn.chatgpt.com/docs/extend/mcp?surface=cli): 프로젝트 `.codex/config.toml`과 STDIO command/args/env/cwd를 지원한다. 프로젝트 설정은 신뢰된 프로젝트에서 읽힌다. 설정 저장을 실제 연결 완료로 표시하지 않는다.
- [공식 Skill 안내](https://learn.chatgpt.com/docs/build-skills): 프로젝트 `.agents/skills`의 SKILL.md를 검색한다. 설치 파일을 이 위치로 제한하고, 미반영 시 다시 연결하는 안내를 제공한다.
- [공식 설정 우선순위](https://learn.chatgpt.com/docs/config-file/config-basic): 상위 정책과 다른 설정이 영향을 줄 수 있다. 앱은 신뢰·승인·계정 설정을 자동 변경하지 않는다.
- [VS Code 시작 안내](https://code.visualstudio.com/docs/getstarted/getting-started): 시작 흐름과 후속 안내를 연결한다. 이 앱에도 진행 단계, 다시 열기, 실패 위치와 재시도를 적용한다.
- [GitHub Desktop 로컬 저장소 추가](https://docs.github.com/en/desktop/adding-and-cloning-repositories/adding-a-repository-from-your-local-computer-to-github-desktop): 사용자가 폴더를 선택하는 진입점을 제공한다. 설정 파일 경로를 먼저 요구하던 기존 흐름을 폴더 선택 중심으로 보완한다.

위 문서는 2026-09-27 확인한 설계 근거다. 외부 UI의 사용성 효과를 이 프로젝트에서 측정했다고 주장하지 않는다.

## 사용자 흐름

1. **프로젝트**: 폴더 선택 → Python 환경·기존 설정 확인. 새 프로젝트는 수집 허용 범위를 화면에서 선택하고 설정과 빈 DB 생성. 기존 설정은 그대로 연다. 파일을 자동 수집하지 않는다.
2. **Codex 연결**: 설치 경로, 추가/갱신/유지 여부와 변경할 Jev 설정·Skill을 미리 확인 → **설정 적용**. 다른 설정과 Skill을 보존하고 기존 Jev 파일을 백업한다.
3. **연결 확인**: 로컬 MCP 통신 점검 → 같은 프로젝트를 Codex에서 열고 신뢰 확인 및 MCP 재연결 안내 → 확인 문구 복사. 앱이 생성한 일회성 request_id를 Codex의 workspace_status 호출로 받으면 확인 시각을 표시한다.
4. **사용 시작**: 저장된 작업 화면으로 이동. 확인을 나중에 할 수도 있고, 미확인 상태는 유지한다. 실패하면 입력과 단계가 남고 재시도·설정 되돌리기를 제공한다.

확인 요청 수신은 특정 도구 호출이 서버에 도착했다는 관측이다. 클라이언트 이름은 자가 보고 값이며 현재 열려 있는 Codex 대화의 신원 인증이나 영구 연결 보장이 아니다. CLI·앱 자체 점검으로 이 단계를 통과시키지 않는다. 확인에는 유효 기간과 설정 fingerprint를 두고 설정 변경·복원 시 무효화한다.

## 보존과 복구 규칙

- 기존 프로젝트/DB/모델 프로필은 덮어쓰지 않는다. 홈의 Codex 설정과 다른 프로젝트는 자동 탐색·수정하지 않는다.
- 설치 계획은 파일 내용 hash에 결속한다. 적용 직전 내용이 바뀌면 새 미리보기가 필요하다.
- 백업은 프로젝트 `.local`에 저장한다. 복원 시 설치 후 파일이 바뀌었으면 덮어쓰지 않고 이유를 표시한다. 복원은 앱이 바꾼 연결 파일만 대상으로 하며 작업 DB를 삭제하지 않는다.
- 잘못된 TOML·권한 오류·경로 이탈·동시 변경은 성공으로 처리하지 않는다. 특이한 TOML 표현으로 기존 설정을 안전하게 보존할 수 없으면 쓰기를 중단한다.
- renderer에는 임의 셸, 임의 파일 쓰기나 임의 도구 호출 API를 노출하지 않는다. 신뢰된 메인 프로세스의 폴더 선택과 제한된 설치 동작만 제공한다.
