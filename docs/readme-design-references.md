# README 레퍼런스와 화면 캡처

이 문서는 0.3.4 화면을 사용한 README 개편 기록이다. 이후 추가된 0.4.0 연결 안내 화면과 검증은 [온보딩 결과](desktop-onboarding-results.md)를 참고한다.

2026-09-27, 인기 오픈소스 프로젝트의 공식 GitHub README를 읽고 Jev Context의 소개 구조에 적용했다. 별 수는 조사 당시 GitHub가 표시한 반올림 수치이며 계속 바뀐다. 인기도는 사례 선정 기준이지 README 디자인의 효과를 입증하는 지표가 아니다.

## 참고한 프로젝트

| 공식 저장소 | 관측한 별 수 | 확인한 구성 | 적용한 부분 |
|---|---:|---|---|
| [Ollama](https://github.com/ollama/ollama) | 약 181.8k | 짧은 제품 소개, 플랫폼별 시작 경로, 실행 명령과 문서 | 간결한 소개와 모델 없는 빠른 시작 |
| [RAGFlow](https://github.com/infiniflow/ragflow) | 약 91.3k | 상단 문서 탐색, 목차, 기능과 설치 절차 구분 | 핵심 섹션 탐색 링크와 목적별 문서 표 |
| [LobeHub](https://github.com/lobehub/lobehub) | 약 82.8k | 브랜드 제목, 사이트·문서 링크, 기능 소개 전 제품 데모 영상 | 로고와 소개의 시각적 위계, 상단 실제 제품 화면 |

타사 로고·스크린샷·카피를 복제하지 않았다. 기존 Jev 로고의 연두색과 앱의 어두운 화면을 사용하고, 상단의 작은 라벨은 라이선스·지원 환경으로 제한한다. CI 라벨은 2026-09-28 원격 검사 제거에 맞춰 삭제했다. 외부 배지 이미지가 로컬 미리보기에서 로드되지 않아 최종본에는 외부 이미지 요청 없이 표시되는 텍스트 링크를 사용했다. 개발 버전과 모델 판단의 제한은 상단에도 표시한다.

## README의 읽는 순서

1. 로고, 한 문장 소개, 핵심 탐색 링크
2. 실제 작업 화면과 세 가지 기능
3. 모델 없이 실행하는 빠른 시작
4. 데스크톱 빠른 실행 화면, 단축키와 빌드 방법
5. 데이터 흐름과 펼쳐 읽는 MCP 계약
6. 검증 현황, 개발 명령과 목적별 문서

긴 설치 세부 절차, 도구 목록, 과거 실험은 `details`로 접어 첫 방문자가 제품과 시작 경로를 먼저 볼 수 있게 했다. 현재 제한과 상세 검증 자료의 링크는 접힌 영역 밖에도 남겼다.

## 다시 촬영하기

[촬영 스크립트](../scripts/capture_readme.cjs)는 Node.js와 `playwright`를 사용할 수 있는 환경에서 프로젝트 루트 기준으로 실행한다.

```powershell
node scripts/capture_readme.cjs
```

빌드된 앱과 유효한 프로젝트 설정, 기존의 `문맥 효율 개선 계획 적용` 작업이 필요하다. 다른 설치에서는 스크립트의 작업 제목을 공개해도 되는 실제 작업으로 변경한다. Playwright가 별도 경로에 설치돼 있으면 해당 `node_modules`를 `NODE_PATH`로 지정한다. 촬영 중 실제 앱 창이 잠시 표시된다.

스크립트는 `.local/readme-capture/user-data`에 분리된 앱 환경을 사용하고 종료 시 자신이 연 앱을 닫는다. PNG 두 장은 `docs/images`에, 촬영 시각·앱 버전·모델 상태·이미지 해시·화면 오류 기록은 `.local/readme-capture/capture.json`에 남긴다. 캡처를 갱신하면 위 촬영 정보도 함께 갱신한다.

## 표시 확인

`marked`로 변환한 로컬 Markdown 미리보기를 Edge에서 1152px와 390px 너비로 열어 확인했다. 최종본의 로고·스크린샷 3개가 모두 로드됐고, README의 링크 67개 중 로컬 파일 대상과 내부 섹션 링크에 누락이 없었다. 390px 너비에서 페이지 전체의 가로 넘침은 없었다. 촬영 스크립트의 `node --check`와 수정 문서의 `git diff --check`도 통과했다.

미리보기는 GitHub와 유사한 간단한 스타일을 적용한 로컬 표시 검사다. GitHub에 게시한 최종 렌더링을 검증한 것은 아니다. 이 작업에서는 앱 기능이나 모델 성능을 변경하지 않았다.
