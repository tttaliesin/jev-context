# 관리 앱 기본 UX 재적용 계획

## 0.3.4 · 공식 브랜드 사례에 근거한 수정

사용자 피드백: “다른 브랜드 모범사례 찾아서 계획하고 다시 적용해”. 0.3.3의 기본 기능 검증은 타 브랜드 조사와 사용성 근거를 대신하지 못했다. [공식 사례 조사](desktop-ux-references.md)를 먼저 작성하고 아래 순서로 재적용한다.

| 단계 | 근거 | 적용할 변화 | 확인 기준 |
| --- | --- | --- | --- |
| 1 · 탐색 공간 | R1 Notion, R2 Linear | 사이드바 완전 접기, 기본 260px·220–400px 드래그/키보드 폭 조절, 폭 기억. 작은 화면에서는 본문 공간에 맞춰 상한을 낮춘다 | 접힘 폭 0, 숨은 포커스 없음, 재실행 복원, 마우스·방향키·Home/End·Enter, 경계 더블클릭으로 기본 폭 |
| 2 · 검색 범위 | R3 Linear | 사이드바 필터는 Ctrl+F와 ‘불러온 작업 필터’로 변경. 현재 개수와 추가 페이지 존재를 명시하고 빈 결과에서 초기화·다음 페이지 경로 제공 | 제목·목표 필터와 전체 저장소 검색을 혼동시키지 않음. 추가 페이지를 읽어도 필터·선택 유지 |
| 3 · 동작 발견 | R4 VS Code, R5 Raycast | 상단 ‘빠른 실행’ / Ctrl+K. 명령·불러온 기록을 검색하고 화살표·Enter로 실행, Esc로 닫기. 관련 액션·단축키·비활성 이유 표시 | 접힌 상태에서도 사용, 한글 조합 중 실행 금지, 현재 모델 버튼과 같은 가능 조건, 단순 열기·검색은 모델 무기동, 프로젝트 바뀌면 결과도 갱신 |
| 4 · 읽기와 위치 | R6 Linear | 상단에 프로젝트와 선택 기록 맥락 유지. 조회 시각은 하단으로 이동. 자동 조회는 목록을 흔들지 않고 수동 로딩·실패는 명시 | 긴 한국어와 작은 창·125% 확대에서 핵심 조작 접근, 갱신 전후 스크롤·포커스 유지, 오류를 정상으로 숨기지 않음 |

Ctrl+K의 의미는 0.3.3 ‘목록 검색’에서 ‘빠른 실행’으로 바뀐다. 기존 목록 검색은 Ctrl+F로 옮기고 상단 버튼·입력 힌트·F1 안내를 함께 바꾼다. 현재 모델 수명·연결 구분·작업 원문·프로젝트별 선택 복원·인라인 재시도는 유지한다.

구현 후 기존 시나리오를 변경된 계약에 맞게 갱신하고, 새 폭 조절·빠른 실행·검색 범위 검증을 추가한다. 실제 EXE에서 재실행·접힘·단축키·최소 창·확대를 확인한 뒤 소스와 패키지 일치를 검증한다. 검증 전에는 0.3.4를 완료로 표시하지 않는다.

### 0.3.4 적용 결과

2026-09-26 위 네 단계를 적용했다. 사이드바 폭·완전 접기·필터 범위·조회 표시와 현재 작업 위치는 `desktop/renderer/index.html`, `style.css`, `renderer.js`에 반영했다. 빠른 실행의 검색·키보드·포커스 처리는 `command-menu.js`에 두고, 실행 가능 조건과 작업 선택은 기존 renderer 상태에 연결했다. Primer의 폭 기억·더블클릭 복원과 WAI의 경계 키보드 조작을 1단계의 보완 근거로 적용했다.

UI 시나리오 **42/42**, 창 상태 경계값 **6/6**, 실제 EXE 재실행 **6단계**, 최소 창·125% 확대 검사를 통과했다. 패키지 12개 파일을 최종 소스와 대조하고 기존 backend 55개 파일 및 원본 런타임이 바뀌지 않았음을 확인했다. 공식 사례와 자체 설계의 구분도 별도 검토했으며, 사용자 연구를 수행하거나 사용성 향상을 측정한 것은 아니다. 대상 해시와 검사별 범위·근거는 [0.3.4 검증 기록](desktop-manager.md#034-검증-기록)에 남겼다.

## 이전 0.3.3 적용 기록

요청: “사이드바 접는거나 뭐 기본적인 ux 기능들좀 정리해서 계획하고 적용해라”

기준 버전은 Electron 0.3.2이며, 아래 다섯 흐름을 0.3.3에 적용한다. 모델 준비·종료 정책, 작업 원문, 코딩 대화를 Codex에서 진행하는 범위는 유지한다.

| 우선순위 | 현재 불편 | 적용 | 확인 기준 |
| --- | --- | --- | --- |
| 1 | 작업 목록이 항상 본문 너비를 차지한다 | 버튼·Ctrl+B로 사이드바를 접고 선택을 기억한다. 접힌 상태에서도 검색 버튼과 Ctrl+K로 펼쳐 검색한다 | 접힌 영역에 키보드 포커스가 남지 않고, 재실행 후 상태가 유지된다 |
| 2 | 다시 열면 읽던 작업·검색어와 창 배치가 초기화된다 | 프로젝트별 선택 ID·검색어만 로컬 UI 설정으로 보관한다. 창 위치·크기·최대화는 별도 파일로 보관한다 | 저장 ID는 실제 저장소에서 다시 확인한다. 다른 프로젝트에 검색/선택이 섞이지 않고, 모니터가 바뀌어도 창을 찾을 수 있다 |
| 3 | 같은 항목을 다시 눌러도 상세가 비워지고 읽던 위치를 잃는다 | 같은 작업 재선택과 자동 갱신은 위치를 유지하고, 다른 작업을 선택할 때만 본문을 처음으로 이동한다 | 목록·상세 스크롤 유지, 작은 화면의 문서 스크롤까지 확인한다 |
| 4 | 상세 조회가 실패해도 전체 새로고침만 가능하다 | 상세 내부에 직접 재시도 버튼을 제공하고 목록·상세 로딩을 구분한다 | 재시도는 해당 작업 조회만 실행한다. 과거 오류가 정상 조회 후 남지 않고, 모델 동작을 자동 재전송하지 않는다 |
| 5 | 진단 팝오버를 키보드로 닫기 어렵고 단축키를 찾기 어렵다 | Esc·바깥 클릭으로 진단창을 닫고, F1/도움말 버튼으로 단축키 안내를 연다. 검색 Enter로 첫 결과를 연다 | 팝오버·대화상자 닫기와 포커스 복귀, 한글 조합 중 키 무시, 실제 구현한 단축키만 안내한다 |

## 상태 저장 범위

- 사이드바 접힘은 앱 전체 UI 설정이다.
- 선택 작업 ID와 검색어는 프로젝트 설정 경로와 프로젝트 ID로 구분한다. 작업 본문, 모델 상태, 페이지 커서는 저장하지 않는다.
- 복원한 작업이 첫 페이지 밖에 있으면 실제 조회에 성공한 항목을 목록에 표시한다. 접근할 수 없는 작업은 과거 본문을 보여주지 않고 재시도할 수 있게 한다.
- 창 상태는 `window-state.json`에 저장하며 프로젝트 선택용 `settings.json`과 분리한다. 잘못된 저장값은 기본값으로 되돌린다.

## 적용과 검증

HTML/CSS 구조, renderer 상호작용, native 창 복원을 나누어 적용한다. 기존 상태 검증에 사이드바·검색·프로젝트 복원·직접 재시도·포커스·스크롤 시나리오를 추가하고, 실제 패키징 EXE에서 접힘과 재실행을 확인한다. 기본 창·최소 창·125% 확대에서 주요 조작이 화면 밖으로 밀리지 않는지 확인한다.

2026-09-26, 다섯 항목 모두 0.3.3에 적용했다. UI 시나리오 30개, 창 상태 경계값 6개, 실제 EXE 재실행 6단계와 최소 창·125% 확대 검사를 통과했다. 같은 작업을 읽는 동안 요청이 끝나도 현재 스크롤을 유지하며, 로딩 표시가 본문을 밀지 않도록 했다. 도움말 닫기와 포커스 복원은 빠른 재진입에서도 일관되게 처리한다.

가상 상태 검사와 실제 Windows 실행의 범위를 나눈 결과·근거 경로는 [실행 안내](desktop-manager.md)에 기록했다. 모델 실행 정책과 작업 저장 계약은 변경하지 않았다.
