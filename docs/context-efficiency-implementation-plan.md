# 문맥 효율 개선 실행 계획

2026-09-27. 근거: [외부 조사](context-efficiency-research.md). 사용자 요청: “적용 계획해서 문서로 만들고 그대로 진행해줘”.

## 목표와 범위

현재 상태·유효한 제약·필요한 근거가 먼저 전달되도록 바꾸고, 과거 이력은 참조로 조회할 수 있게 한다. 저장 원문·이벤트·실패·반대 근거를 삭제하지 않는다. 현재 계약 2.0을 개선하며 1.0의 기존 동작은 유지한다. 기존 다른 세션의 변경을 보존한다.

로컬 모델의 active 승격은 독립 품질 평가가 필요한 후속 단계다. 이번 실행은 그 전제인 문맥 구성·재개 검증과 판단 결과 분리를 완료한다. 외부 성능 수치를 목표 달성으로 대신하지 않는다.

## 실행 순서와 완료 기준

| 순서 | 적용 내용 | 완료 기준 |
| --- | --- | --- |
| 1. 현재 상태 | 완료된 작업의 progress를 완료 요약·남은 항목에서 구성. 재개 시 오래된 다음 행동 초기화. context에도 현재 상태 포함 | 신규 기록과 기존 저장 작업 모두 완료/진행 상태가 모순되지 않고 원본 이벤트는 조회 가능 |
| 2. 이력 분리 | 대체된 완료 기준은 ID·이유·revision으로 축약. 실패/반대 근거는 claim·유형·검증 핵심·상세 조회 참조로 제공 | 현행 제약·미해결 충돌·반대 근거 핵심 보존. 상세 criteria/evidence 조회 가능. DB 원본 불변 |
| 3. 근거 우선 전달 | 저장 가능한 판단 상세는 기본 응답에서 분리. 필수 발췌와 겹치는 검색 결과 제거. 근거의 경로·revision 유지 | 필수 발췌 보존, 긴 한 행의 서로 다른 바이트 청크를 오인해 제거하지 않음, 판단 상세 재조회 가능 |
| 4. 예산 상태 | 본문/전송 예산으로 근거가 생략되면 partial·누락 수를 표시하고 최종 본문 크기 재계산 | 예산 초과 없음. 검색 결과가 밀려났는데 ok인 경우 없음. 필수 항목은 조용히 삭제하지 않음 |
| 5. 모델 없는 재개 검증 | 완료/재개, 변경된 원문, 과거 revision, 방해 자료, 부정·상충 및 정보 없음 사례 회귀. 기존 실제 작업으로 수정 전후 비교 | 동일 작업 revision·query·source·예산 비교에서 근거 보존/전송량 관측. 보호 항목 및 이력 접근 검증 |
| 6. 통합·문서화 | 전체 검사, 실제 MCP 새 프로세스 점검, 사용 문서와 결과 갱신 | 명령·종료 코드·소스 hash·측정 범위 기록. 모델/코딩 성능 개선 미검증과 기능 완료 구분 |

## 설계 제약

- 축약은 반환 표현에만 적용한다. 저장된 criteria·evidence·event를 변경하지 않는다.
- 사용자 제약·미해결 issue/adopted decision·실패/반대 claim은 임의 문자열 절단 없이 보존한다. 상세 observation은 검증 결과 식별 정보와 원본 조회 경로를 남긴다.
- 필수 원문 참조는 계속 읽고 보존한다. 중복 제거는 같은 source/revision의 실제 행·바이트 포함 관계를 확인한 경우만 수행한다.
- read-only 호출은 저장하지 못한 판단 상세를 조회 가능하다고 표시하지 않는다.
- 전송 바이트는 토큰·청구 비용과 구별한다. 판단 상세에 대한 기존 호출자는 work_inspect(view=judgments)를 사용하도록 문서화한다.
- GPU 자동 시작, 모델 교체, 상시 실행, 임의 threshold 변경은 포함하지 않는다. 다중 후보 판단의 정확도·보류·보정과 prefix/batch 이식은 독립 평가 이후 판단한다.

## 검증 절차

새 회귀를 먼저 실행하고 전체 lint/format/pytest를 수행한다. Windows 임시 경로는 짧은 프로젝트 내 새 경로로 고정한다. 실제 저장 작업은 읽기 전후 비교 대상으로 사용하고 과거 기록을 고쳐 결과를 만들지 않는다. native 연결이 기존 서버 코드를 유지하면 새 stdio MCP 프로세스로 확인하고 현재 대화의 서버 교체 여부는 별도 표시한다.

시간·비용을 쓰는 새 Codex 코딩 비교는 먼저 필요한 기능 검증과 사람이 검토한 평가 입력이 갖춰진 다음 진행한다. 이번 실행에서 새 에이전트 작성 사례를 사람 검토 heldout이라고 부르지 않는다.

## 실행 결과

1~6번 구현·검증·문서화를 마쳤다. 최종 lint·format과 전체 검사 270개가 통과했고 기존 Windows symlink 권한 조건 1개가 제외됐다. 세부 근거는 [적용 결과](context-efficiency-results.md)에 기록한다.

- 현재 상태·이력 분리: 신규/기존 완료 작업과 재개 회귀 확인. 원본 이벤트는 유지한다.
- 근거 우선·예산 상태: 중복 포함 관계, 과거 revision, 긴 행 조각, 필수 원문, 누락 상태를 확인했다.
- 실제 저장 작업: work revision 36과 원문 hash를 유지한 비교에서 필수 본문 14,885→11,590바이트, 40KB 예산의 근거 1→2개. 두 MCP 프로세스에서 같은 상태·근거를 복원했고 원본 기록 hash가 같았다.
- 모델 단계: 판단 상세의 분리와 조회, off 경로의 추론 미실행을 확인했다. active 승격·실제 한국어 분류 보정·일반 코딩 효율은 계획대로 독립 평가 조건이 남아 있다.
