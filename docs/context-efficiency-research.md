# 문맥·로컬 판단 효율 개선을 위한 외부 조사

조사일: 2026-09-27. 논문 원문, 제작사의 기술 문서, SemIf 작성자의 공개 구현을 확인했다. 아래 적용안은 외부 결과와 현재 코드에 근거한 제안이며 이 프로젝트에서 성능 개선이 검증된 결과는 아니다. 제품 코드·모델 설정은 변경하지 않았다.

## 판단

우선순위는 **현재 작업 상태를 작게 복원하는 기본 경로 → 필요한 근거만 추가로 읽는 경로 → 검증된 경우에만 로컬 판단으로 후보를 줄이는 경로**다. 저장량 증가와 입력 문맥 증가는 분리해야 한다.

기존 [실험](resume-evaluation-results.md)은 한 결함에 대해 E0/E1/E2를 세 번씩 비교했다. E2는 원문을 보존하는 shadow 주석 조건이었다. 능동 선별·압축의 효용을 측정하지 않았으며, 추가 판단이 시간 초과를 일으켰다는 인과관계도 입증하지 않았다. 따라서 로컬 모델을 즉시 교체하거나 활성화할 근거는 부족하다.

## 현재 구현에서 확인한 문제

### 1. 과거 기록이 현재 근거의 자리를 차지한다

`src/jev_context/context.py::_work_state`는 모든 완료 기준을 보호 대상으로 넣는다. `not_applicable`로 대체된 기준도 포함한다. 실패·반대 근거 보존은 필요하지만 전체 과거 객체를 매번 보내는 방식은 저장과 전달을 결합한다.

이번 조사 중 native MCP로 기존 작업 revision 36을 복원하고 다음 조건으로 재확인했다. **아래는 기존 9회 비교와 다른, 조사 중 수행한 읽기 관측이다.**

- work: `work-f53e94c849424d43bb42783a2a9bb5f6`, `judge_mode=off`.
- query: `문맥 효율 비교 한계 shadow`, source 범위: 기존 결과 문서 하나.
- 40,000바이트 전송 예산에서 보호 항목 21개. 그중 완료 기준 12개는 대체됨 8개·통과 4개였다.
- 응답은 `ok`였지만 선택적 근거 6개가 전송 예산 단계에서 빠져 실제 `evidence`는 0개였다. 최종 전송 크기는 32,894바이트였다.
- 관측 기록: `.local/external-research-20260927/context-receipt.json`. 바이트는 토큰과 다르며 전송 크기에는 text/structuredContent의 중복이 포함된다. 호스트가 둘 다 모델 입력으로 보내는지는 확인하지 않았다.

`work_open`에도 완료 요약과 아직 06~09 실행을 다음 행동으로 적은 과거 progress가 함께 있었다. 완료 이벤트와 현재 상태 투영을 일관되게 만드는 일이 필요하다. 원본 이벤트를 지우거나 실패를 숨길 이유는 없다.

### 2. shadow는 비용 절감을 실행하지 않는다

`judgment.py::select_evidence`의 제외·축약은 목적별 active 승격이 필요하다. 현재 프로필은 shadow이며 승격은 모두 false다. 이것은 검증되지 않은 판단으로 자료를 버리지 않기 위한 정상적인 제한이다. 다만 이 상태를 능동 필터의 효율 실험으로 부를 수 없다.

상세 판단을 `work_inspect`로 읽는 기능은 이미 있다. 현재 `budget.py::bounded`는 예산을 넘을 때만 상세 evaluations를 응답에서 뺀다. 기본 응답에서 항상 상세 관측을 분리하는 옵션은 추가 후보다.

### 3. 검색과 추론 최적화는 기존 기능 위에서 해야 한다

`sources.py::search`에는 이미 경로·문자열 일치, lexical/trigram FTS의 BM25, 순위 결합이 있다. BM25나 다중 검색 경로를 새로 도입한다고 제안하면 기존 구현을 잘못 설명하게 된다. 다음 후보는 검색 청크의 맥락·중복·누락 분석과 필요한 경우의 의미 검색이다.

`semif_worker.py::answer`의 confidence는 선택 확률의 정규화 엔트로피에서 계산한다. 경험적으로 보정한 정답률이 아니다. 두 관측의 거의 균일한 확률만으로 모델 전체가 실패했다고 할 수도 없지만, 자동 제외를 허용할 근거도 없다. 현재 모델 준비 약 45초, 문맥 판단 약 1.9초의 측정은 따로 계산해야 한다.

## 권장 변경 순서

### P0 — 현재 상태와 이력의 전달 경로 분리

1. 최신 목표·유효 제약·미해결 문제·완료 요약·다음 행동을 일관된 상태로 구성한다. 완료된 작업에는 오래된 실행 계획이 다음 행동으로 노출되지 않게 한다.
2. 대체된 완료 기준은 ID·대체 이유·조회 참조로 표현하고 전체 객체는 이력 조회에 남긴다. 현재 유효한 제약과 미해결 충돌은 반드시 본문에 보존한다. 실패·반대 근거도 존재와 핵심 내용을 기본 응답에서 알 수 있어야 한다.
3. 기본 문맥에 현재 과제의 핵심 발췌와 고정 revision·행 참조를 싣고, 반복 메타데이터와 상세 판단 추적은 별도 조회로 보낸다. 원문·이력 삭제는 하지 않는다.
4. 보호 항목만으로 예산이 찼다면 검색 근거를 제공하지 못했다는 상태를 명확히 알린다. 명목상 `ok`와 실질적인 근거 확보를 구분한다.

확인 기준: 제약·미해결 반대 근거 보존, 대체된 기준의 추적 가능성, 완료/진행 상태 일치, 동일 질의의 근거 누락 및 전송 바이트. 줄인 요약 때문에 추가 조회가 얼마나 늘어나는지도 센다. 구체적인 응답 예산은 자료별 크기를 본 뒤 정한다.

### P1 — 추론 없이도 유용한 재개 경로 검증

명시한 파일·정책·최근 변경·현재 질문과 직접 관련된 발췌를 우선한다. 전체 진행 서술을 복제하지 않는다. 파일의 제목·절·경로를 검색 청크의 식별 정보로 유지하고, 겹치는 발췌를 합친다. 검색 범위·최신성·미검색 범위는 계속 표시한다.

이 단계에서 모델 없이 새 문맥의 정확한 재개가 가능한지 측정한다. 자료가 없거나 오래됐으면 추측하지 않고 원문을 다시 읽게 한다. 의미 검색은 현재 검색의 실제 누락 사례가 있어야 비교 대상으로 넣는다.

### P2 — 로컬 모델의 역할을 좁혀 검증

많은 후보에서 애매한 관련성을 구별해야 할 때만 로컬 판단을 시험한다. 필수 제약·명시 원문·미해결 반대 근거는 자동 제외 대상이 아니다. 판단 목적과 옵션 순서, 한국어 부정·예외·경로 이름에 따른 변화를 별도 평가한다.

정답이 있는 학습/보정 자료와 독립 평가 자료를 분리한다. 잘못된 제외율, 보류율, 남은 근거 재현율을 함께 본다. 확률 보정으로 분류 정확도가 개선됐다고 주장하지 않는다. 승격 조건은 유지한다.

반복 판단 캐시는 query·목표/제약·source revision/hash·목적·프롬프트/옵션·모델 fingerprint를 포함한 키와 무효화 규칙이 필요하다. 같은 상태의 많은 판단이 실제 병목일 때만 prefix 재사용 또는 batching을 시험한다. 현재 고정 길이 OpenVINO IR의 지원 여부와 결과 동등성은 미확인이다. 상시 GPU 실행으로 준비 비용을 숨기지 말고 최초 실행·준비된 상태·유휴 자원을 각각 보고한다.

## 다음 평가 설계

같은 한 결함을 오래 반복하는 대신 다음 축으로 과제를 나눈다. 이는 연구에서 그대로 가져온 정답 세트가 아니라 프로젝트용 제안이다.

| 과제 유형 | 구별하려는 효과 |
| --- | --- |
| 현재 요청만으로 충분한 작은 수정 | 불필요한 문맥/모델 호출을 생략하는가 |
| 이전 세션의 결정이 필요한 재개 | 저장 기억이 빠뜨린 정보를 복원하는가 |
| 요구사항 변경·낡은 결과·서로 다른 revision | 최신 상태를 고르고 과거와 구별하는가 |
| 관련 자료와 유사한 방해 자료가 많은 검색 | 선택이 근거를 보존하면서 읽기 비용을 줄이는가 |
| 정보 부재·상충·한국어 부정/예외 | 보류·제약 보존이 제대로 작동하는가 |

먼저 공개된 개발 사례로 P0/P1의 상태·검색 품질을 빠르게 점검한다. 이후 사람 검토가 끝난 독립 과제에서 기본 실행, 현재 문맥, 축소한 문맥, 축소 문맥+검증된 선별을 비교한다. 마지막 조건은 승격 기준 충족 전까지 격리된 평가에서만 실행한다. 모델 설정은 같게 유지하고 조건 순서를 교대한다.

주 지표는 **정답·제약 준수와 제한 내 완료율**이다. 성공한 실행만 고른 시간 중앙값은 보조 지표로 두고, 실패·시간 초과·시도별 관측 사용량을 모두 보고한다. 모델 준비/검색/판단/수정/검증/최종 보고 시간을 구분하고 초기 입력 크기뿐 아니라 재조회와 누적 입력도 센다. 최초 정답 시점은 사전 정의한 체크포인트에서 실제로 검사한 경우만 보고한다.

Windows 임시 경로·테스트 명령·권한·정리 절차를 먼저 고정한다. 정답 검사는 모든 조건에 동일하게 적용한다. 사용량 제한 발생 시 중단하며, 제한 늘리기로 특정 조건의 실패를 성공으로 바꾸지 않는다. 과제 수와 반복 수, 품질 허용 오차, 비용 개선 기준은 독립 평가를 보기 전에 정하고 소표본 결과를 일반 성능 주장으로 확장하지 않는다.

권장 착수점은 P0다. 지금 확인된 문맥 낭비와 상태 불일치를 직접 다루며, 모델 교체·새 서비스 도입·GPU 상시 가동 없이 검증할 수 있다.
